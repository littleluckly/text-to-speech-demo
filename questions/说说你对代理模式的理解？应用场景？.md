## 答案 1：核心简洁的口语化回答

・代理模式是通过一个代理对象控制对原对象的访问，起到中介作用

・核心作用是在不改变原对象的前提下，增加额外功能（如权限控制、缓存、日志）

・代理与原对象实现相同接口，客户端无需区分两者

・常见类型：保护代理（权限控制）、虚拟代理（延迟加载）、缓存代理（结果缓存）

・适用于图片懒加载、接口请求代理、权限验证等场景

## 答案 2：口语化扩展回答

代理模式就像是生活中的中介，比如租房时的中介，你通过中介找房东租房，中介在中间会做一些事情，比如筛选房源、核实信息，但最终还是和房东产生实际交易。在代码里，就是用一个代理对象来包裹真实对象，所有对真实对象的访问都要经过代理。

这种模式的好处很明显，能在不改动原有代码的情况下，给功能增加额外的处理。比如加载一张很大的图片，直接加载可能影响页面性能，这时候可以用虚拟代理，先显示占位图，等图片加载完成再替换，这就是代理帮我们做了延迟加载的工作。

实际开发中用得挺多的，比如接口请求时，代理可以帮我们加请求头、处理错误；或者做权限控制，代理先检查用户有没有权限，有了再调用真实接口。还有缓存代理，比如计算一些复杂结果后，代理会把结果存起来，下次再要同样的结果就直接返回，不用重新计算了。代理和原对象接口一样，用的时候直接换就行，不影响其他代码。

## 答案 3：技术深度解析

### 代理模式的本质与核心结构

代理模式（Proxy Pattern）属于结构型设计模式，其核心思想是**通过引入一个代理对象，间接访问目标对象**，从而在不修改目标对象的前提下，为其增加额外功能或控制访问。

代理模式的经典结构包含三个部分：



1.  **抽象主题（Subject）**：定义目标对象和代理对象的共同接口，确保代理可被当作目标对象使用

2.  **目标对象（Real Subject）**：实际执行业务逻辑的对象，是代理的目标

3.  **代理对象（Proxy）**：实现抽象主题接口，持有目标对象的引用，控制对目标对象的访问，并可添加额外操作

这种结构遵循 "开闭原则"，可以在不修改目标对象和客户端代码的情况下，灵活扩展功能。

### 代理模式的实现方式

#### 1. 基础实现框架



```
// 1. 抽象主题 - 定义共同接口

class Subject {

&#x20; request() {

&#x20;   throw new Error("子类必须实现request方法");

&#x20; }

}

// 2. 目标对象 - 实际业务逻辑

class RealSubject extends Subject {

&#x20; /\*\*

&#x20;  \* 实际的请求处理

&#x20;  \* @returns {string} 处理结果

&#x20;  \*/

&#x20; request() {

&#x20;   // 模拟真实业务逻辑

&#x20;   return "真实对象处理了请求";

&#x20; }

}

// 3. 代理对象 - 控制访问并添加功能

class ProxySubject extends Subject {

&#x20; /\*\*

&#x20;  \* 初始化代理

&#x20;  \* @param {RealSubject} realSubject - 目标对象

&#x20;  \*/

&#x20; constructor(realSubject) {

&#x20;   super();

&#x20;   this.realSubject = realSubject; // 持有目标对象引用

&#x20; }

&#x20;&#x20;

&#x20; /\*\*

&#x20;  \* 代理的请求方法

&#x20;  \* @returns {string} 处理结果

&#x20;  \*/

&#x20; request() {

&#x20;   // 前置处理

&#x20;   this.beforeRequest();

&#x20;  &#x20;

&#x20;   // 调用目标对象的方法

&#x20;   const result = this.realSubject.request();

&#x20;  &#x20;

&#x20;   // 后置处理

&#x20;   this.afterRequest();

&#x20;  &#x20;

&#x20;   return result;

&#x20; }

&#x20;&#x20;

&#x20; /\*\*

&#x20;  \* 请求前的额外操作

&#x20;  \*/

&#x20; beforeRequest() {

&#x20;   console.log("代理：请求前的准备工作");

&#x20; }

&#x20;&#x20;

&#x20; /\*\*

&#x20;  \* 请求后的额外操作

&#x20;  \*/

&#x20; afterRequest() {

&#x20;   console.log("代理：请求后的清理工作");

&#x20; }

}

// 使用示例

// 创建目标对象

const realSubject = new RealSubject();

// 创建代理对象，包裹目标对象

const proxy = new ProxySubject(realSubject);

// 客户端通过代理访问，无需知道真实对象

console.log(proxy.request());

// 输出：

// 代理：请求前的准备工作

// 真实对象处理了请求

// 代理：请求后的清理工作
```

#### 2. ES6 Proxy 实现（JavaScript 特色）

JavaScript 的 Proxy 对象原生支持代理模式，提供了更灵活的实现方式：



```
// 目标对象

const target = {

&#x20; name: "目标对象",

&#x20; doSomething: function() {

&#x20;   return \`\${this.name}执行了操作\`;

&#x20; }

};

// 代理处理器

const handler = {

&#x20; // 拦截属性访问

&#x20; get(target, prop, receiver) {

&#x20;   console.log(\`访问了属性：\${prop}\`);

&#x20;   // 可以添加权限控制等逻辑

&#x20;   if (prop === 'secret' && !isAuthenticated()) {

&#x20;     throw new Error("没有权限访问该属性");

&#x20;   }

&#x20;   return Reflect.get(target, prop, receiver);

&#x20; },

&#x20;&#x20;

&#x20; // 拦截方法调用

&#x20; apply(target, thisArg, argumentsList) {

&#x20;   console.log(\`调用了方法，参数：\${argumentsList}\`);

&#x20;   // 前置处理

&#x20;   const start = Date.now();

&#x20;  &#x20;

&#x20;   // 执行原始方法

&#x20;   const result = Reflect.apply(target, thisArg, argumentsList);

&#x20;  &#x20;

&#x20;   // 后置处理

&#x20;   const end = Date.now();

&#x20;   console.log(\`方法执行耗时：\${end - start}ms\`);

&#x20;  &#x20;

&#x20;   return result;

&#x20; },

&#x20;&#x20;

&#x20; // 拦截属性设置

&#x20; set(target, prop, value, receiver) {

&#x20;   console.log(\`设置属性\${prop}为\${value}\`);

&#x20;   // 可以添加数据验证等逻辑

&#x20;   if (prop === 'age' && (value < 0 || value > 150)) {

&#x20;     throw new Error("年龄必须在0-150之间");

&#x20;   }

&#x20;   return Reflect.set(target, prop, value, receiver);

&#x20; }

};

// 创建代理对象

const proxy = new Proxy(target, handler);

// 使用代理

console.log(proxy.name); // 访问属性会被拦截

proxy.age = 25; // 设置属性会被拦截

proxy.doSomething(); // 调用方法会被拦截
```

### 代理模式的常见类型与应用场景

#### 1. 虚拟代理（Virtual Proxy）

延迟创建开销大的对象，直到真正需要时才创建，常用于优化性能。

**图片懒加载实现**：



```
// 图片加载目标对象

class RealImage {

&#x20; /\*\*

&#x20;  \* 初始化真实图片

&#x20;  \* @param {string} src - 图片地址

&#x20;  \*/

&#x20; constructor(src) {

&#x20;   this.src = src;

&#x20;   this.loadImage(); // 加载图片（耗时操作）

&#x20; }

&#x20;&#x20;

&#x20; /\*\*

&#x20;  \* 显示图片

&#x20;  \* @param {HTMLElement} container - 容器元素

&#x20;  \*/

&#x20; display(container) {

&#x20;   const img = document.createElement('img');

&#x20;   img.src = this.src;

&#x20;   container.appendChild(img);

&#x20; }

&#x20;&#x20;

&#x20; /\*\*

&#x20;  \* 实际加载图片

&#x20;  \*/

&#x20; loadImage() {

&#x20;   console.log(\`正在加载图片：\${this.src}\`);

&#x20;   // 模拟网络请求延迟

&#x20;   return new Promise(resolve => {

&#x20;     setTimeout(() => {

&#x20;       console.log(\`图片加载完成：\${this.src}\`);

&#x20;       resolve();

&#x20;     }, 1000);

&#x20;   });

&#x20; }

}

// 图片代理（虚拟代理）

class ImageProxy {

&#x20; /\*\*

&#x20;  \* 初始化图片代理

&#x20;  \* @param {string} src - 图片地址

&#x20;  \*/

&#x20; constructor(src) {

&#x20;   this.src = src;

&#x20;   this.realImage = null; // 延迟初始化真实图片

&#x20;   this.placeholder = 'data:image/gif;base64,R0lGODlhAQABAAAAACH5BAEKAAEALAAAAAABAAEAAAICTAEAOw==';

&#x20; }

&#x20;&#x20;

&#x20; /\*\*

&#x20;  \* 显示图片（代理方法）

&#x20;  \* @param {HTMLElement} container - 容器元素

&#x20;  \*/

&#x20; display(container) {

&#x20;   // 先显示占位图

&#x20;   const placeholderImg = document.createElement('img');

&#x20;   placeholderImg.src = this.placeholder;

&#x20;   placeholderImg.className = 'placeholder';

&#x20;   container.appendChild(placeholderImg);

&#x20;  &#x20;

&#x20;   // 当图片进入视口时才加载真实图片

&#x20;   const observer = new IntersectionObserver(entries => {

&#x20;     entries.forEach(entry => {

&#x20;       if (entry.isIntersecting && !this.realImage) {

&#x20;         // 真正需要时才创建真实图片对象

&#x20;         this.realImage = new RealImage(this.src);

&#x20;         // 加载完成后替换占位图

&#x20;         this.realImage.loadImage().then(() => {

&#x20;           container.removeChild(placeholderImg);

&#x20;           this.realImage.display(container);

&#x20;         });

&#x20;         observer.disconnect();

&#x20;       }

&#x20;     });

&#x20;   });

&#x20;  &#x20;

&#x20;   observer.observe(placeholderImg);

&#x20; }

}

// 使用

const container = document.getElementById('image-container');

// 使用代理加载图片，而非直接使用RealImage

const image = new ImageProxy('https://example.com/large-image.jpg');

image.display(container);
```

#### 2. 保护代理（Protection Proxy）

控制对目标对象的访问权限，常用于权限验证。

**接口请求权限控制**：



```
// 真实接口服务

class ApiService {

&#x20; getUserInfo(userId) {

&#x20;   return \`用户\${userId}的信息\`;

&#x20; }

&#x20;&#x20;

&#x20; deleteUser(userId) {

&#x20;   return \`用户\${userId}已删除\`;

&#x20; }

&#x20;&#x20;

&#x20; getDashboardData() {

&#x20;   return "仪表盘数据";

&#x20; }

}

// 权限代理

class ProtectedApiProxy {

&#x20; constructor(apiService, userRole) {

&#x20;   this.apiService = apiService;

&#x20;   this.userRole = userRole; // 用户角色：admin/user/guest

&#x20; }

&#x20;&#x20;

&#x20; // 公共接口，所有角色可访问

&#x20; getUserInfo(userId) {

&#x20;   return this.apiService.getUserInfo(userId);

&#x20; }

&#x20;&#x20;

&#x20; // 受保护接口，只有管理员可访问

&#x20; deleteUser(userId) {

&#x20;   // 权限检查

&#x20;   if (this.userRole !== 'admin') {

&#x20;     throw new Error("权限不足：只有管理员可删除用户");

&#x20;   }

&#x20;   // 权限通过，调用真实服务

&#x20;   return this.apiService.deleteUser(userId);

&#x20; }

&#x20;&#x20;

&#x20; // 受保护接口，管理员和普通用户可访问

&#x20; getDashboardData() {

&#x20;   if (\['admin', 'user'].includes(this.userRole)) {

&#x20;     return this.apiService.getDashboardData();

&#x20;   }

&#x20;   throw new Error("权限不足：请先登录");

&#x20; }

}

// 使用示例

const realApi = new ApiService();

// 普通用户访问

const userProxy = new ProtectedApiProxy(realApi, 'user');

console.log(userProxy.getUserInfo(123)); // 正常访问

console.log(userProxy.getDashboardData()); // 正常访问

try {

&#x20; userProxy.deleteUser(123); // 权限不足

} catch (e) {

&#x20; console.log(e.message);

}

// 管理员访问

const adminProxy = new ProtectedApiProxy(realApi, 'admin');

console.log(adminProxy.deleteUser(123)); // 正常访问
```

#### 3. 缓存代理（Cache Proxy）

为目标对象的计算结果提供缓存，避免重复计算。

**计算结果缓存**：



```
// 复杂计算服务

class CalculationService {

&#x20; /\*\*

&#x20;  \* 计算斐波那契数列（耗时操作）

&#x20;  \* @param {number} n - 数列索引

&#x20;  \* @returns {number} 第n项的值

&#x20;  \*/

&#x20; fibonacci(n) {

&#x20;   console.log(\`计算fibonacci(\${n})\`);

&#x20;   if (n <= 1) return n;

&#x20;   // 递归计算，效率低，适合缓存

&#x20;   return this.fibonacci(n - 1) + this.fibonacci(n - 2);

&#x20; }

&#x20;&#x20;

&#x20; /\*\*

&#x20;  \* 计算两数乘积

&#x20;  \* @param {number} a - 第一个数

&#x20;  \* @param {number} b - 第二个数

&#x20;  \* @returns {number} 乘积

&#x20;  \*/

&#x20; multiply(a, b) {

&#x20;   console.log(\`计算\${a} \* \${b}\`);

&#x20;   return a \* b;

&#x20; }

}

// 缓存代理

class CacheProxy {

&#x20; constructor(service) {

&#x20;   this.service = service;

&#x20;   this.cache = new Map(); // 缓存容器

&#x20; }

&#x20;&#x20;

&#x20; /\*\*

&#x20;  \* 带缓存的斐波那契计算

&#x20;  \* @param {number} n - 数列索引

&#x20;  \* @returns {number} 计算结果

&#x20;  \*/

&#x20; fibonacci(n) {

&#x20;   // 生成缓存键

&#x20;   const key = \`fib\_\${n}\`;

&#x20;  &#x20;

&#x20;   // 检查缓存

&#x20;   if (this.cache.has(key)) {

&#x20;     console.log(\`从缓存获取fibonacci(\${n})\`);

&#x20;     return this.cache.get(key);

&#x20;   }

&#x20;  &#x20;

&#x20;   // 无缓存，调用真实服务计算

&#x20;   const result = this.service.fibonacci(n);

&#x20;  &#x20;

&#x20;   // 存入缓存

&#x20;   this.cache.set(key, result);

&#x20;  &#x20;

&#x20;   return result;

&#x20; }

&#x20;&#x20;

&#x20; /\*\*

&#x20;  \* 带缓存的乘法计算

&#x20;  \* @param {number} a - 第一个数

&#x20;  \* @param {number} b - 第二个数

&#x20;  \* @returns {number} 乘积

&#x20;  \*/

&#x20; multiply(a, b) {

&#x20;   const key = \`mul\_\${a}\_\${b}\`;

&#x20;   if (this.cache.has(key)) {

&#x20;     console.log(\`从缓存获取\${a} \* \${b}\`);

&#x20;     return this.cache.get(key);

&#x20;   }

&#x20;  &#x20;

&#x20;   const result = this.service.multiply(a, b);

&#x20;   this.cache.set(key, result);

&#x20;   return result;

&#x20; }

&#x20;&#x20;

&#x20; /\*\*

&#x20;  \* 清除缓存

&#x20;  \*/

&#x20; clearCache() {

&#x20;   this.cache.clear();

&#x20;   console.log("缓存已清除");

&#x20; }

}

// 使用示例

const calcService = new CalculationService();

const cacheProxy = new CacheProxy(calcService);

// 第一次计算，无缓存

console.log(cacheProxy.fibonacci(10)); // 会实际计算

// 第二次计算，使用缓存

console.log(cacheProxy.fibonacci(10)); // 从缓存获取

// 乘法计算缓存

console.log(cacheProxy.multiply(5, 8)); // 实际计算

console.log(cacheProxy.multiply(5, 8)); // 从缓存获取
```

### 代理模式的优缺点分析

**优点**：



*   符合单一职责原则：目标对象专注于业务逻辑，代理专注于附加功能

*   符合开闭原则：可在不修改目标对象和客户端的情况下添加新功能

*   提高系统灵活性：可动态切换代理类型或增减代理功能

*   保护目标对象：通过代理控制访问，隐藏目标对象细节

**缺点**：



*   增加系统复杂度：引入代理层可能使代码结构更复杂

*   增加访问延迟：代理的额外处理会带来一定性能开销

*   可能导致调试困难：多层代理可能使问题定位变得
