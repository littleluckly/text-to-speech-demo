## 答案 1：核心简洁的口语化回答

・受控组件：表单数据由 React 的 state 管理，通过 onChange 事件更新 state，表单值与 state 同步。

・非受控组件：表单数据由 DOM 自身管理，通过 ref 获取 DOM 元素来读取值，不依赖 state。

・受控组件适合需要实时验证、动态禁用 / 启用按钮、多字段联动等场景。

・非受控组件适合简单表单、文件上传、集成第三方 UI 库等场景，实现更简洁。

・受控组件可完全控制表单行为，非受控组件更接近原生 DOM 操作。

## 答案 2：口语化扩展回答

受控组件和非受控组件主要是 React 中处理表单元素的两种方式，核心区别在于数据由谁管理。

受控组件就像被 React “牢牢控制” 的组件，表单里的输入值（比如输入框的文字、复选框的勾选状态）都存在 React 的 state 里。用户每次输入时，都会触发 onChange 事件，我们在事件处理函数里更新 state，而表单元素的值又会从 state 里取，这样表单值和 state 就始终保持同步。这种方式的好处是能随时掌握表单的状态，比如做实时验证，输入不对就立刻提示；或者根据输入内容决定按钮是否可点击，用起来很灵活。

非受控组件则更 “自由”，表单数据由 DOM 自己管，就像原生 HTML 表单那样。要获取值的时候，得通过 ref 拿到 DOM 元素，再从元素里读值。它不用写那么多事件处理函数，代码更简单，适合那些不需要复杂逻辑的简单表单。比如只是收集用户姓名和邮箱的表单，提交时一次性获取就行，没必要实时监控每一次输入。不过它的缺点也明显，没法实时控制表单状态，想做实时验证之类的功能就比较麻烦。

实际开发中，大部分场景推荐用受控组件，尤其是需要对表单做复杂处理的时候；简单场景或者处理文件上传（因为文件输入比较特殊）时，用非受控组件更方便。

## 答案 3：技术深度解析

### 受控组件与非受控组件的本质区别

在 React 中，受控组件和非受控组件是处理表单元素（如 input、select、textarea 等）的两种核心模式，其本质区别在于**表单数据的管理方式**：



*   **受控组件**：表单数据由 React 组件的 state 完全控制，形成 “数据驱动” 的单向数据流。

*   **非受控组件**：表单数据由 DOM 自身管理，React 通过 ref 间接访问数据，更接近原生 HTML 的表单处理方式。

### 技术实现细节

#### 1. 受控组件实现

受控组件的核心是**表单元素的值与 state 绑定**，通过`onChange`事件同步更新 state，形成闭环：



```
function ControlledForm() {

&#x20; // 用state管理表单数据

&#x20; const \[formData, setFormData] = React.useState({

&#x20;   username: '',

&#x20;   email: '',

&#x20;   agree: false

&#x20; });

&#x20; // 统一的事件处理函数

&#x20; const handleChange = (e) => {

&#x20;   const { name, type, value, checked } = e.target;

&#x20;   // 根据输入类型处理值（文本输入取value，复选框取checked）

&#x20;   setFormData(prev => ({

&#x20;     ...prev,

&#x20;     \[name]: type === 'checkbox' ? checked : value

&#x20;   }));

&#x20; };

&#x20; const handleSubmit = (e) => {

&#x20;   e.preventDefault();

&#x20;   // 直接从state获取表单数据

&#x20;   console.log('提交数据:', formData);

&#x20; };

&#x20; return (

&#x20;   \<form onSubmit={handleSubmit}>

&#x20;     {/\* 输入框：value与state绑定，onChange更新state \*/}

&#x20;     \<input

&#x20;       type="text"

&#x20;       name="username"

&#x20;       value={formData.username}  {/\* 受控值 \*/}

&#x20;       onChange={handleChange}    {/\* 同步更新 \*/}

&#x20;       placeholder="用户名"

&#x20;     />

&#x20;     \<input

&#x20;       type="email"

&#x20;       name="email"

&#x20;       value={formData.email}

&#x20;       onChange={handleChange}

&#x20;       placeholder="邮箱"

&#x20;     />

&#x20;     {/\* 复选框：checked与state绑定 \*/}

&#x20;     \<label>

&#x20;       \<input

&#x20;         type="checkbox"

&#x20;         name="agree"

&#x20;         checked={formData.agree}  {/\* 受控状态 \*/}

&#x20;         onChange={handleChange}

&#x20;       />

&#x20;       同意协议

&#x20;     \</label>

&#x20;     \<button type="submit">提交\</button>

&#x20;   \</form>

&#x20; );

}
```

**受控组件的关键特性**：



*   表单元素必须设置`value`（或`checked` for 复选框 / 单选框）

*   必须提供`onChange`事件处理函数更新 state

*   每次用户输入都会触发 re-render，保证 UI 与数据一致

#### 2. 非受控组件实现

非受控组件**不依赖 state**，通过`ref`直接访问 DOM 元素获取值：



```
function UncontrolledForm() {

&#x20; // 创建ref引用表单元素

&#x20; const usernameRef = React.useRef(null);

&#x20; const emailRef = React.useRef(null);

&#x20; const agreeRef = React.useRef(null);

&#x20; const handleSubmit = (e) => {

&#x20;   e.preventDefault();

&#x20;   // 通过ref获取DOM元素的值

&#x20;   const formData = {

&#x20;     username: usernameRef.current.value,

&#x20;     email: emailRef.current.value,

&#x20;     agree: agreeRef.current.checked

&#x20;   };

&#x20;   console.log('提交数据:', formData);

&#x20; };

&#x20; return (

&#x20;   \<form onSubmit={handleSubmit}>

&#x20;     {/\* 输入框：不设置value，通过ref访问 \*/}

&#x20;     \<input

&#x20;       type="text"

&#x20;       ref={usernameRef}  {/\* 绑定ref \*/}

&#x20;       defaultValue=""    {/\* 可选：设置初始值 \*/}

&#x20;       placeholder="用户名"

&#x20;     />

&#x20;     \<input

&#x20;       type="email"

&#x20;       ref={emailRef}

&#x20;       defaultValue=""

&#x20;       placeholder="邮箱"

&#x20;     />

&#x20;     \<label>

&#x20;       \<input

&#x20;         type="checkbox"

&#x20;         ref={agreeRef}

&#x20;         defaultChecked={false}  {/\* 复选框初始值 \*/}

&#x20;       />

&#x20;       同意协议

&#x20;     \</label>

&#x20;     \<button type="submit">提交\</button>

&#x20;   \</form>

&#x20; );

}
```

**非受控组件的关键特性**：



*   不设置`value`/`checked`，而是用`defaultValue`/`defaultChecked`设置初始值

*   通过`ref`获取实时值，无需`onChange`事件

*   只有在需要时（如提交）才读取数据，减少 re-render

#### 3. 特殊表单元素处理

**文件输入框（input type="file"）**：

文件输入框始终是非受控组件，因为其`value`只读（安全限制），必须通过 ref 访问：



```
function FileUpload() {

&#x20; const fileRef = React.useRef(null);

&#x20; const handleUpload = () => {

&#x20;   // 获取选中的文件

&#x20;   const file = fileRef.current.files\[0];

&#x20;   console.log('选中的文件:', file);

&#x20; };

&#x20; return (

&#x20;   \<div>

&#x20;     \<input type="file" ref={fileRef} />

&#x20;     \<button onClick={handleUpload}>上传\</button>

&#x20;   \</div>

&#x20; );

}
```

### 核心差异对比



| 特性    | 受控组件              | 非受控组件                           |
| ----- | ----------------- | ------------------------------- |
| 数据存储  | React state       | DOM 自身                          |
| 取值方式  | 直接从 state 获取      | 通过 ref 访问 DOM 元素                |
| 初始值设置 | `value`/`checked` | `defaultValue`/`defaultChecked` |
| 更新触发  | 每次输入触发 re-render  | 仅在主动读取时获取最新值                    |
| 实时验证  | 容易实现（基于 state 变化） | 较复杂（需监听原生事件）                    |
| 代码量   | 较多（需编写 onChange）  | 较少（无需事件处理）                      |
| 可控性   | 完全可控              | 间接控制                            |

### 适用场景深度分析

#### 受控组件适用场景



1.  **需要实时反馈的表单**：



```
// 实时验证示例

function ValidatedForm() {

&#x20; const \[email, setEmail] = useState('');

&#x20; const \[error, setError] = useState('');

&#x20; const validateEmail = (value) => {

&#x20;   const isValid = /^\[^\s@]+@\[^\s@]+\\.\[^\s@]+\$/.test(value);

&#x20;   setError(isValid ? '' : '请输入有效的邮箱地址');

&#x20; };

&#x20; return (

&#x20;   \<div>

&#x20;     \<input

&#x20;       type="email"

&#x20;       value={email}

&#x20;       onChange={(e) => {

&#x20;         setEmail(e.target.value);

&#x20;         validateEmail(e.target.value); // 实时验证

&#x20;       }}

&#x20;     />

&#x20;     {error && \<span style={{ color: 'red' }}>{error}\</span>}

&#x20;   \</div>

&#x20; );

}
```



*   实时表单验证（如输入密码时提示强度）

*   输入格式限制（如只能输入数字）

*   动态提示或错误信息展示

1.  **多字段联动**：

*   一个字段的变化影响另一个字段（如选择国家后联动城市列表）

*   动态启用 / 禁用表单元素（如勾选 “其他” 后显示输入框）

1.  **需要撤销 / 重做功能**：

*   基于 state 的历史记录管理，可实现表单状态回溯

1.  **复杂表单逻辑**：

*   动态增减表单项（如多联系人表单）

*   分步表单（多步骤填写，需要保存中间状态）

#### 非受控组件适用场景



1.  **简单表单**：

*   仅需提交时获取数据，无需实时处理

*   如登录表单、搜索框等基础场景

1.  **文件上传**：

*   如前所述，文件输入框必须使用非受控方式

1.  **集成第三方 UI 库**：

*   某些 UI 组件不支持受控模式，需通过 ref 操作

1.  **性能优化场景**：



```
// 非受控组件优化高频输入

function SearchInput() {

&#x20; const inputRef = useRef(null);

&#x20; const \[results, setResults] = useState(\[]);

&#x20; // 防抖处理搜索请求

&#x20; const fetchResults = useCallback(

&#x20;   debounce((value) => {

&#x20;     // 发起搜索请求

&#x20;     api.search(value).then(data => setResults(data));

&#x20;   }, 300),

&#x20;   \[]

&#x20; );

&#x20; return (

&#x20;   \<input

&#x20;     ref={inputRef}

&#x20;     onChange={() => fetchResults(inputRef.current.value)}

&#x20;     placeholder="搜索..."

&#x20;   />

&#x20; );

}
```



*   高频输入场景（如实时搜索），减少 re-render 次数

*   可结合`useCallback`和原生事件优化性能

1.  **快速迁移传统表单**：

*   从原生 HTML 表单迁移到 React 时，非受控组件更接近原有逻辑

### 最佳实践与性能考量



1.  **优先使用受控组件**：

*   符合 React 数据驱动的设计理念

*   便于调试和测试（state 可追踪）

*   更易实现复杂交互逻辑

1.  **非受控组件的性能优势**：

*   减少不必要的 re-render（尤其在高频输入场景）

*   适合处理大型表单（减少 state 更新带来的性能开销）

1.  **混合使用策略**：

*   复杂字段用受控模式，简单字段用非受控模式

*   如表单中既有需要实时验证的邮箱字段，又有简单的备注文本框

1.  **避免的反模式**：

*   不要同时设置`value`和`defaultValue`（会导致警告）

*   不要在受控组件中使用 ref 读取值（应直接从 state 获取）

*   非受控组件不要依赖`onChange`同步 state（失去非受控优势）

### 总结

受控组件和非受控组件并非对立关系，而是 React 提供的两种互补的表单处理方式。选择哪种模式取决于具体需求：



*   **受控组件**是 “数据驱动” 的典范，通过 state 完全掌控表单状态，适合需要复杂交互和实时反馈的场景，是大多数 React 应用的首选。

*   **非受控组件**更接近原生 DOM 操作，代码简洁，性能开销小，适合简单场景、文件处理或需要减少 re-render 的场景。

理解两者的本质区别和适用场景，能帮助开发者在实际项目中做出合理选择，编写更高效、更易维护的表单代码。在现代 React 开发中，推荐以受控组件为主，非受控组件为辅，根据具体需求灵活搭配使用。
