## 答案 1：核心简洁的口语化回答

・使用 Set 数据结构：`[...new Set(arr)]`，简洁高效，适合简单场景

・利用对象键名唯一特性：遍历数组将元素作为对象键，再提取键名

・双重循环比对：外层遍历数组，内层检查后续元素，重复则删除，兼容性好但效率低

・先排序再去重：排序后相邻元素对比，相同则去除，适合有序场景

・性能上 Set 最优，双重循环最差；复杂数据类型去重需自定义比对逻辑

## 答案 2：口语化扩展回答

数组去重就是把数组中重复的元素只保留一个，实际开发中处理列表数据时经常会用到。最简单的方法是用 ES6 的 Set，因为 Set 本身就不允许有重复值，把数组转换成 Set 再转回来就行，一行代码`[...new Set(arr)]`特别方便，对于简单类型的数组很适用。

如果要兼容旧环境，不能用 Set 的话，可以用对象来实现。遍历数组时把每个元素作为对象的键名存起来，因为对象键名不能重复，最后把键名取出来就是去重后的数组。不过要注意，这种方法默认会把数字和字符串视为相同键名（比如 1 和 '1'），需要额外处理。

双重 for 循环是最传统的方法，外层循环拿元素，内层循环和后面的元素比较，遇到重复的就删掉。这种方法不用额外空间，但嵌套循环效率低，数组越长速度越慢。还有先排序再去重的方式，排序后相同的元素会挨在一起，只要比较相邻元素就能去重，效率比双重循环好，但会改变原数组的顺序。

不同方法性能差异明显，数据量小时感觉不出来，数据量大的时候 Set 的优势就很明显了。如果是复杂对象数组，还需要根据具体属性去重，这时候就要在遍历中加自定义判断了。

## 答案 3：技术深度解析

### 数组去重的核心原理

数组去重的本质是**识别并移除重复元素**，关键在于如何高效判断元素是否已存在。不同方案的核心差异在于：



*   存储已出现元素的方式（数据结构选择）

*   元素比对的逻辑（全等判断、类型敏感 / 不敏感）

*   对原数组的影响（是否改变顺序、是否修改原数组）

### 常见实现方案及代码

#### 方案 1：使用 Set 数据结构（ES6+）



```
/\*\*

&#x20;\* 使用Set实现数组去重

&#x20;\* @param {Array} arr - 需要去重的数组

&#x20;\* @returns {Array} 去重后的新数组

&#x20;\*/

function uniqueBySet(arr) {

&#x20; // Set自动过滤重复值，再通过扩展运算符转回数组

&#x20; return \[...new Set(arr)];

&#x20;&#x20;

&#x20; // 等价实现：return Array.from(new Set(arr));

}
```

**特性分析**：



*   原理：利用 Set"值唯一且不重复" 的特性

*   类型敏感性：严格区分类型（1 和 '1' 视为不同）

*   顺序：保留元素首次出现的顺序（ES6 后 Set 保持插入顺序）

*   局限性：无法直接处理对象数组（对象引用不同视为不同）

#### 方案 2：利用对象键名唯一性



```
/\*\*

&#x20;\* 使用对象实现数组去重（基础版）

&#x20;\* @param {Array} arr - 需要去重的数组

&#x20;\* @returns {Array} 去重后的新数组

&#x20;\*/

function uniqueByObjectBasic(arr) {

&#x20; const obj = {};

&#x20; const result = \[];

&#x20;&#x20;

&#x20; for (let i = 0; i < arr.length; i++) {

&#x20;   const item = arr\[i];

&#x20;   // 将元素作为对象键名（自动转为字符串）

&#x20;   const key = typeof item + item; // 解决1和'1'被视为相同的问题

&#x20;  &#x20;

&#x20;   if (!obj.hasOwnProperty(key)) {

&#x20;     obj\[key] = true; // 标记为已存在

&#x20;     result.push(item);

&#x20;   }

&#x20; }

&#x20;&#x20;

&#x20; return result;

}
```

**特性分析**：



*   原理：对象键名具有唯一性，通过键名判断元素是否已存在

*   类型处理：基础版通过`typeof item + item`解决类型混淆问题

*   顺序：保留元素首次出现的顺序

*   局限性：对象元素仍会被视为不同（因为对象.toString () 结果通常为 "\[object Object]"）

#### 方案 3：双重循环比对



```
/\*\*

&#x20;\* 双重循环实现数组去重

&#x20;\* @param {Array} arr - 需要去重的数组

&#x20;\* @returns {Array} 去重后的新数组

&#x20;\*/

function uniqueByDoubleLoop(arr) {

&#x20; // 创建原数组的拷贝，避免修改原数组

&#x20; const result = \[...arr];

&#x20;&#x20;

&#x20; // 外层循环遍历所有元素

&#x20; for (let i = 0; i < result.length; i++) {

&#x20;   // 内层循环比对当前元素之后的所有元素

&#x20;   for (let j = i + 1; j < result.length; j++) {

&#x20;     // 严格相等判断

&#x20;     if (result\[i] === result\[j]) {

&#x20;       // 移除重复元素（会改变数组长度）

&#x20;       result.splice(j, 1);

&#x20;       // 修正索引（因为删除元素后后面元素前移）

&#x20;       j--;

&#x20;     }

&#x20;   }

&#x20; }

&#x20;&#x20;

&#x20; return result;

}
```

**特性分析**：



*   原理：通过嵌套循环逐一比对元素，发现重复则移除

*   类型敏感性：严格区分类型（使用 === 判断）

*   顺序：保留原始顺序，但会修改数组结构（splice 方法）

*   局限性：时间复杂度高，性能较差

#### 方案 4：先排序后去重



```
/\*\*

&#x20;\* 先排序后去重

&#x20;\* @param {Array} arr - 需要去重的数组

&#x20;\* @returns {Array} 去重后的新数组

&#x20;\*/

function uniqueBySort(arr) {

&#x20; // 空数组直接返回

&#x20; if (arr.length === 0) return \[];

&#x20;&#x20;

&#x20; // 排序（会改变元素顺序）

&#x20; const sortedArr = \[...arr].sort((a, b) => {

&#x20;   // 处理不同类型元素的排序

&#x20;   if (typeof a !== typeof b) return typeof a > typeof b ? 1 : -1;

&#x20;   return a > b ? 1 : -1;

&#x20; });

&#x20;&#x20;

&#x20; const result = \[sortedArr\[0]];

&#x20;&#x20;

&#x20; // 遍历排序后的数组，只保留与前一个元素不同的元素

&#x20; for (let i = 1; i < sortedArr.length; i++) {

&#x20;   if (sortedArr\[i] !== result\[result.length - 1]) {

&#x20;     result.push(sortedArr\[i]);

&#x20;   }

&#x20; }

&#x20;&#x20;

&#x20; return result;

}
```

**特性分析**：



*   原理：排序后重复元素会相邻，只需比对相邻元素

*   类型敏感性：通过自定义排序函数处理类型差异

*   顺序：会改变原数组顺序（排序导致）

*   优势：时间复杂度优于双重循环

#### 方案 5：对象数组去重（按指定属性）



```
/\*\*

&#x20;\* 对象数组按指定属性去重

&#x20;\* @param {Array} arr - 对象数组

&#x20;\* @param {string} prop - 用于去重的属性名

&#x20;\* @returns {Array} 去重后的数组

&#x20;\*/

function uniqueObjectArray(arr, prop) {

&#x20; const map = new Map();

&#x20; return arr.filter(item => {

&#x20;   // 使用属性值作为Map的键

&#x20;   const key = item\[prop];

&#x20;   // 如果键不存在则保留该元素，并将键存入Map

&#x20;   if (!map.has(key)) {

&#x20;     map.set(key, true);

&#x20;     return true;

&#x20;   }

&#x20;   return false;

&#x20; });

}
```

**特性分析**：



*   原理：利用 Map 存储对象属性值，判断是否重复

*   灵活性：可指定任意属性作为去重依据

*   应用场景：后端返回的列表数据去重（如按 id 去重）

#### 性能分析



1.  **Set 方法性能最优**：

*   底层使用哈希表实现，查找速度快（时间复杂度 O (1)）

*   原生实现经过浏览器 / JS 引擎优化，效率极高

*   数据量越大，优势越明显

1.  **对象方法次之**：

*   原理类似 Set，但对象属性访问有额外开销

*   类型处理逻辑会增加少量性能损耗

*   在不支持 Set 的环境中是较好选择

1.  **排序后去重**：

*   性能依赖排序算法（JS 引擎通常使用快速排序或 Timsort）

*   时间复杂度为 O (n log n)，优于双重循环但不及哈希表方法

*   适合允许改变数组顺序的场景

1.  **双重循环性能最差**：

*   时间复杂度为 O (n²)，数据量增大时耗时呈指数增长

*   频繁调用 splice 方法会导致数组重构，性能损耗大

*   仅适合极小规模数组或兼容性要求极高的场景

### 适用场景选择



| 场景               | 推荐方法              | 理由         |
| ---------------- | ----------------- | ---------- |
| 简单类型数组（数字、字符串）   | Set 方法            | 简洁高效，性能最优  |
| 需兼容 ES5 及以下环境    | 对象方法              | 无依赖，兼容性好   |
| 大型数组（10 万 + 元素）  | Set 方法            | 性能优势明显     |
| 允许改变元素顺序         | 排序后去重             | 平衡性能与实现复杂度 |
| 对象数组按属性去重        | Map / 对象 + filter | 可自定义去重依据   |
| 极旧浏览器环境（IE8 及以下） | 双重循环              | 无任何 API 依赖 |

### 特殊情况处理



1.  **NaN 的去重**：

*   Set 会将 NaN 视为相同值（尽管 NaN !== NaN）

*   其他方法需要特殊处理：`if (item !== item) { /* 处理NaN */ }`

1.  **对象数组去重**：

*   需根据具体属性去重（如 id）

*   复杂对象可序列化后去重（`JSON.stringify(item)`）

1.  **保留最后一次出现的元素**：

*   反向遍历数组，覆盖已存在的元素

*   示例：`arr.reduceRight((acc, cur) => (acc.includes(cur) ? acc : [cur, ...acc]), [])`

### 总结

数组去重的实现方案各有优劣，选择时需综合考虑：



*   数据规模（小 / 中 / 大型数组）

*   数据类型（简单类型 / 对象数组）

*   性能要求

*   兼容性要求

在现代 JS 环境中，**Set 方法**是大多数场景的最优选择，兼具简洁性和高性能。对于特殊场景（如对象数组、旧环境兼容），可根据具体需求选择合适的方案。理解不同方案的原理和性能差异，有助于在实际开发中做出最优决策。
