## 答案 1：核心简洁的口语化回答

・CSSOM（CSS 对象模型）是解析 CSS 后生成的树形结构，包含所有样式规则及继承、层叠关系。

・它需与 DOM 结合生成渲染树，此过程会阻塞页面渲染。

・复杂的 CSS 选择器、大量样式规则会延长 CSSOM 构建时间，增加渲染阻塞时长，降低页面加载速度。

・媒体查询可让部分 CSS 不阻塞渲染，优化性能。

## 答案 2：口语化扩展回答

CSSOM 其实就是浏览器把 CSS 代码解析后形成的一种数据结构，像棵树一样，里面清晰地记录了所有的样式规则，包括每个元素该怎么显示，还有样式之间的继承和覆盖关系。比如说，一个 p 标签的颜色可能继承了 body 的样式，又被自己的 class 样式覆盖，这些关系在 CSSOM 里都能体现出来。

它对页面渲染性能的影响还挺直接的。浏览器要先把 CSSOM 和 DOM 合并成渲染树才能继续后面的布局和绘制步骤，而在 CSSOM 没构建完的时候，渲染过程会被卡住，页面就没法显示。如果 CSS 代码写得很复杂，比如用了很多嵌套的选择器，浏览器解析起来就慢，CSSOM 构建时间变长，页面加载自然就延迟了。

不过也有办法优化，比如给一些 CSS 加媒体查询，像打印样式，浏览器会先下载但不阻塞渲染，这样能加快首屏显示。平时写 CSS 时少用复杂选择器，减少不必要的样式，也能让 CSSOM 构建更快，提升页面渲染性能。

## 答案 3：技术深度解析

### 1. 什么是 CSSOM？

CSSOM（CSS Object Model，CSS 对象模型）是浏览器解析 CSS 样式表后生成的**树形数据结构**，用于描述页面中所有元素的样式规则及样式之间的层叠、继承关系。

#### 1.1 CSSOM 的核心特点



*   **树形结构**：与 DOM 类似，根节点为全局样式（如 html 元素的默认样式），子节点对应 DOM 元素的样式规则。

*   **包含所有样式信息**：包括浏览器默认样式（user-agent stylesheet）、开发者编写的样式（内联、嵌入、外部样式表）、用户自定义样式（如浏览器字体大小设置）。

*   **支持样式计算**：能根据层叠规则（cascade）、继承（inheritance）和特异性（specificity）计算每个元素的最终样式。

#### 1.2 CSSOM 的构建过程

### 2. CSSOM 如何影响页面渲染性能？

页面渲染流程需经历 “DOM 构建 → CSSOM 构建 → 渲染树构建 → 布局 → 绘制 → 合成” 六个阶段，其中**CSSOM 是连接 DOM 与渲染树的关键环节**，其构建效率直接影响渲染性能。

#### 2.1 阻塞渲染的特性



*   **CSSOM 构建会阻塞渲染树生成**：渲染树依赖 DOM 和 CSSOM 的结合，若 CSSOM 未完成，浏览器会暂停渲染流程，等待 CSS 解析完成。

*   **阻塞 JavaScript 执行**：JavaScript 可能操作 CSS 样式（如`getComputedStyle`），因此浏览器会先等待 CSSOM 构建完成，再执行 JavaScript，形成 “CSS 阻塞 JS → JS 阻塞 DOM 解析 → 最终阻塞渲染” 的连锁反应。

#### 2.2 样式复杂度对性能的影响



*   **选择器解析成本**：复杂选择器（如嵌套层级深的后代选择器、属性选择器）会增加 CSSOM 的构建时间。例如：


    *   高效选择器：`#header`（ID 选择器，直接定位）

    *   低效选择器：`div:nth-child(2) > .container ~ p`（需遍历多个节点验证关系）

*   **样式规则数量**：大量冗余样式规则会增大 CSSOM 体积，导致内存占用增加，同时延长样式计算时间（尤其是在元素数量多的页面中）。

#### 2.3 与 DOM 的协同成本

渲染树构建阶段，浏览器需为每个 DOM 节点匹配 CSSOM 中的样式规则，这一过程的复杂度随 DOM 和 CSSOM 规模增长而显著提升。例如：



*   当 DOM 节点数为 N，CSS 规则数为 M 时，最坏情况下匹配时间复杂度为 O (N×M)。

*   复杂的选择器匹配逻辑（如伪类、属性匹配）会进一步增加单节点的匹配成本。

### 3. 优化 CSSOM 以提升渲染性能的实践

#### 3.1 减少 CSSOM 构建时间



*   **精简 CSS 代码**：移除未使用的样式（可通过 PurgeCSS 等工具），避免冗余规则。

*   **优化选择器**：


    *   优先使用 ID 选择器、类选择器，减少后代选择器嵌套（建议不超过 3 层）。

    *   避免使用通配符（`*`）和属性选择器（如`[type="text"]`）遍历大量节点。

*   **拆分 CSS 文件**：使用媒体查询（`@media`）区分不同场景的样式（如`print`、`screen`），浏览器会异步下载非关键媒体查询的 CSS，不阻塞首屏渲染。



```
/\* 非关键CSS（打印样式）不会阻塞首屏渲染 \*/

@media print {

&#x20; body {

&#x20;   font-size: 12px;

&#x20;   color: #000;

&#x20; }

}
```

#### 3.2 降低样式计算成本



*   **利用 CSSOM 缓存**：浏览器会缓存已计算的样式，避免重复计算。避免频繁通过 JavaScript 动态修改样式（如`element.style`），可通过切换 class 实现样式变更。

*   **减少样式继承链**：避免深层嵌套 DOM 结构，减少样式继承的计算量。例如，对深层子元素直接设置样式，而非依赖祖先元素的继承。

#### 3.3 优先加载关键 CSS



*   **内联关键 CSS**：将首屏必需的样式内联到`<style>`标签中，减少外部 CSS 文件的请求延迟，加速 CSSOM 构建。

*   **异步加载非关键 CSS**：通过`<link rel="preload" as="style" onload="this.rel='stylesheet'">`异步加载非首屏样式，避免阻塞渲染。

### 4. 总结

CSSOM 是页面渲染的核心数据结构，其构建效率和复杂度直接影响渲染性能。由于 CSSOM 具有阻塞渲染和 JavaScript 执行的特性，优化 CSSOM 的关键在于：减少样式规则复杂度、拆分非关键样式、优先加载首屏 CSS。通过合理的 CSS 架构设计和性能优化手段，可显著缩短 CSSOM 构建时间，提升页面渲染速度和用户体验。
