## 答案 1：核心简洁的口语化回答

・箭头函数没有自己的 this，其 this 继承自外层作用域，且无法通过 call、apply、bind 改变；普通函数 this 随调用方式变化。

・箭头函数不能作为构造函数，无法使用 new 关键字；普通函数可以。

・箭头函数没有 arguments 对象，需用剩余参数...args 替代；普通函数有 arguments。

・箭头函数不能使用 yield，不能作为生成器函数；普通函数可以。

・箭头函数语法更简洁，适合短逻辑函数；普通函数语法相对繁琐。

## 答案 2：口语化扩展回答

箭头函数和普通函数在使用起来差别还挺明显的。先说 this，箭头函数的 this 就像 "继承" 来的，从它定义时的外层作用域拿，之后不管怎么调用都不会变。普通函数的 this 就灵活多了，谁调用它，this 就指向谁，比如对象调用时指向对象，全局调用可能指向 window 或者 undefined。

还有构造函数这块，箭头函数根本不能当构造函数用，用 new 调用会报错，普通函数就可以，能用来创建实例。另外，箭头函数里没有 arguments 这个东西，如果想拿所有参数，得用...args 这种剩余参数。

不过箭头函数写起来确实简洁，像那种一行就能搞定的函数，用箭头函数特别方便。但也不是所有地方都能用，比如对象里的方法，如果用箭头函数，this 就不是指向对象本身了，会出问题。还有事件处理函数，用箭头函数的话，this 可能就不是指向事件源了，不太方便。

## 答案 3：技术深度解析

### 箭头函数与普通函数的特性差异详解

#### 1. this 绑定机制不同

这是箭头函数与普通函数最核心的差异。

普通函数的 this 绑定具有动态性，其值取决于函数的调用方式：



*   当函数作为对象的方法调用时，this 指向该对象

*   当函数作为普通函数调用时，this 在非严格模式下指向全局对象（window/global），严格模式下为 undefined

*   当使用 call、apply、bind 方法调用时，this 指向传入的第一个参数

*   当作为构造函数使用 new 调用时，this 指向新创建的实例对象

箭头函数没有自己的 this 绑定，其 this 值继承自外层作用域的 this，且在函数创建后永久固定，无法通过 call、apply、bind 等方法改变。

**代码示例**：



```
// 普通函数的this

const obj1 = {

&#x20; name: 'obj1',

&#x20; func: function() {

&#x20;   console.log(this.name);

&#x20; }

};

const obj2 = { name: 'obj2' };

obj1.func(); // 输出 'obj1'，this指向obj1

obj1.func.call(obj2); // 输出 'obj2'，this被改为指向obj2

// 箭头函数的this

const obj3 = {

&#x20; name: 'obj3',

&#x20; func: () => {

&#x20;   console.log(this.name);

&#x20; }

};

const obj4 = { name: 'obj4' };

obj3.func(); // 输出 undefined（非严格模式下this指向window，window.name为空）

obj3.func.call(obj4); // 仍输出 undefined，this无法被改变
```

#### 2. 构造函数能力

普通函数可以作为构造函数使用，通过 new 关键字创建实例：



```
function Person(name) {

&#x20; this.name = name;

}

const person = new Person('张三'); // 正确，person为Person的实例
```

箭头函数不能作为构造函数，使用 new 调用会抛出错误：



```
const Person = (name) => {

&#x20; this.name = name;

};

const person = new Person('张三'); // 报错：Person is not a constructor
```

这是因为箭头函数没有 \[\[Construct]] 内部方法，无法创建新的实例对象。

#### 3. arguments 对象

普通函数内部有 arguments 对象，它是一个类数组对象，包含了函数调用时的所有参数：



```
function sum() {

&#x20; let total = 0;

&#x20; for (let i = 0; i < arguments.length; i++) {

&#x20;   total += arguments\[i];

&#x20; }

&#x20; return total;

}

sum(1, 2, 3); // 输出 6
```

箭头函数没有 arguments 对象，如果需要获取所有参数，需使用剩余参数语法...args：



```
const sum = (...args) => {

&#x20; let total = 0;

&#x20; for (let i = 0; i < args.length; i++) {

&#x20;   total += args\[i];

&#x20; }

&#x20; return total;

};

sum(1, 2, 3); // 输出 6
```

剩余参数 args 是一个真正的数组，相比 arguments 使用更灵活，支持数组的所有方法。

#### 4. 函数原型与 yield 关键字

普通函数有 prototype 属性，而箭头函数没有：



```
function normalFunc() {}

console.log(normalFunc.prototype); // 输出 {constructor: f}

const arrowFunc = () => {};

console.log(arrowFunc.prototype); // 输出 undefined
```

另外，箭头函数不能使用 yield 关键字，因此不能作为生成器函数；普通函数可以：



```
// 普通函数作为生成器

function\* generatorFunc() {

&#x20; yield 1;

&#x20; yield 2;

}

// 箭头函数不能作为生成器，以下代码会报错

const generatorArrow =\* () => { // 语法错误

&#x20; yield 1;

};
```

#### 5. 语法形式

箭头函数的语法更简洁，有以下几种形式：



*   单个参数时可以省略括号：`param => expression`

*   函数体为单个表达式时可以省略大括号和 return：`(param1, param2) => param1 + param2`

*   函数体有多行代码时需要用大括号包裹并显式使用 return：`(a, b) => { const c = a + b; return c * 2; }`

普通函数则必须使用 function 关键字声明，且函数体即使是单个表达式也需要用大括号包裹（除非使用简写形式，但不常见）。

### 不适合使用箭头函数的场景

#### 1. 对象的方法

当定义对象的方法时，不适合使用箭头函数，因为箭头函数的 this 不会指向调用该方法的对象，而是继承自外层作用域。

**反例**：



```
const user = {

&#x20; name: '张三',

&#x20; getName: () => {

&#x20;   return this.name; // this指向外层作用域（如window），而非user对象

&#x20; }

};

console.log(user.getName()); // 输出 undefined
```

**正例**：



```
const user = {

&#x20; name: '张三',

&#x20; getName: function() {

&#x20;   return this.name; // this指向user对象

&#x20; }

};

console.log(user.getName()); // 输出 '张三'
```

#### 2. 事件处理函数

在事件处理函数中，通常需要通过 this 获取事件源（触发事件的 DOM 元素），而箭头函数的 this 无法指向事件源，因此不适合。

**反例**：



```
const button = document.getElementById('myButton');

button.addEventListener('click', () => {

&#x20; this.textContent = '已点击'; // this不指向button元素，而是外层作用域

});
```

**正例**：



```
const button = document.getElementById('myButton');

button.addEventListener('click', function() {

&#x20; this.textContent = '已点击'; // this指向button元素

});
```

#### 3. 需要动态 this 的场景

当函数需要根据调用方式动态改变 this 指向时，不能使用箭头函数。例如，在实现工厂模式或需要借用其他对象方法的场景。

**反例**：



```
const obj1 = { value: 10 };

const obj2 = { value: 20 };

const getValue = () => {

&#x20; return this.value;

};

console.log(getValue.call(obj1)); // 输出 undefined，this无法指向obj1
```

**正例**：



```
const obj1 = { value: 10 };

const obj2 = { value: 20 };

function getValue() {

&#x20; return this.value;

}

console.log(getValue.call(obj1)); // 输出 10，this指向obj1

console.log(getValue.call(obj2)); // 输出 20，this指向obj2
```

#### 4. 构造函数

如前所述，箭头函数不能作为构造函数，因此在需要创建实例对象的场景，必须使用普通函数。

**反例**：



```
const Car = (brand) => {

&#x20; this.brand = brand;

};

const myCar = new Car('特斯拉'); // 报错
```

**正例**：



```
function Car(brand) {

&#x20; this.brand = brand;

}

const myCar = new Car('特斯拉'); // 正确，myCar为Car的实例
```

#### 5. 需要使用 arguments 对象的场景

虽然剩余参数可以替代 arguments，但在一些老代码或需要直接操作 arguments 对象的场景（如判断参数长度、修改参数值等），普通函数更合适。

**示例**：



```
// 需要使用arguments的情况

function logArgs() {

&#x20; console.log('参数个数：', arguments.length);

&#x20; for (let arg of arguments) {

&#x20;   console.log(arg);

&#x20; }

}

logArgs(1, 'a', true);

// 箭头函数需用剩余参数

const logArgsArrow = (...args) => {

&#x20; console.log('参数个数：', args.length);

&#x20; for (let arg of args) {

&#x20;   console.log(arg);

&#x20; }

};
```

虽然功能可以实现，但如果是维护已有代码，且代码中大量使用了 arguments，此时将函数改为箭头函数会增加修改成本。

### 总结

箭头函数是 ES6 引入的一种新的函数形式，它在 this 绑定、构造函数能力、arguments 对象等方面与普通函数有显著差异，语法上也更简洁。在实际开发中，应根据具体场景选择合适的函数形式：箭头函数适合用于回调函数、简单的逻辑处理等场景，能简化代码；而在对象方法、事件处理函数、构造函数等需要动态 this 或特定功能的场景，则不适合使用箭头函数，普通函数仍是更好的选择。理解两者的差异和适用场景，有助于写出更清晰、更可靠的 JavaScript 代码。
