## 答案 1：核心简洁的口语化回答

・命令模式封装 “操作请求”，关注 “做什么”，支持撤销、日志等功能；策略模式封装 “算法家族”，关注 “怎么做”，支持算法动态切换

・命令模式中命令对象包含接收者，策略模式中策略对象不依赖特定接收者

・命令模式侧重操作的封装与管理，策略模式侧重算法的替换与选择

・前端中，命令模式适用于操作历史（如编辑器撤销）、任务队列（如批量请求）；策略模式适用于表单验证规则、支付方式切换等场景

・核心区别：命令模式处理 “操作的执行与管理”，策略模式处理 “算法的选择与替换”

## 答案 2：口语化扩展回答

命令模式和策略模式虽然都用了封装的思想，但解决的问题不一样。命令模式就像把一个个操作打包成命令，比如点击按钮提交表单这个操作，会被封装成一个命令对象，里面包含了具体怎么提交的逻辑。这样做的好处是可以轻松实现撤销、记录日志，比如编辑器里的撤销功能，就是把之前的命令存起来，需要撤销时调用对应命令的 undo 方法。

策略模式则是为了应对不同的算法或规则，比如表单验证，不同的字段可能有不同的验证策略（手机号验证、邮箱验证），这些策略可以被单独封装，然后根据需要切换使用。它不关心操作本身，而是关注用什么方法去完成一件事，而且策略之间是可以互相替换的，比如支付时切换微信支付或支付宝支付，这两种支付策略就能用策略模式来管理。

在前端开发中，命令模式适合那些需要记录操作历史、支持撤销重做的场景，比如富文本编辑器、表单设计器。而策略模式更适合那些有多种方案可选，且方案之间可以灵活切换的场景，比如表格的排序方式、图表的展示样式等。

## 答案 3：技术深度解析

### 命令模式与策略模式的核心区别

两种设计模式均通过封装实现代码复用，但在设计目标、结构和应用场景上存在本质差异：



| 维度   | 命令模式（Command Pattern）                            | 策略模式（Strategy Pattern）                    |
| ---- | ------------------------------------------------ | ----------------------------------------- |
| 核心目标 | 封装 “操作请求”，实现请求发送者与执行者的解耦                         | 封装 “算法家族”，实现算法的灵活替换与选择                    |
| 封装内容 | 完整的操作流程（包含 “做什么” 和 “谁来做”）                        | 算法的具体实现（仅包含 “怎么做”）                        |
| 角色关系 | 包含命令（Command）、接收者（Receiver）、调用者（Invoker），命令依赖接收者 | 包含策略（Strategy）、上下文（Context），策略独立于上下文      |
| 核心方法 | 强调 `execute()`（执行）和 `undo()`（撤销）                 | 强调算法的核心执行方法（如 `calculate()`、`validate()`） |
| 典型功能 | 支持操作撤销、日志记录、任务队列                                 | 支持算法动态切换、策略组合                             |
| 设计意图 | 关注操作的 “执行与管理”                                    | 关注算法的 “选择与替换”                             |

### 前端中的适用场景举例

#### 1. 命令模式的典型应用场景

##### （1）富文本编辑器的操作管理

富文本编辑器需要支持操作撤销 / 重做、操作日志记录等功能，命令模式能完美满足这些需求：



```
// 命令基类

class EditorCommand {

&#x20; constructor(editor) {

&#x20;   this.editor = editor; // 接收者：编辑器实例

&#x20;   this.previousState = ''; // 保存操作前的状态

&#x20; }

&#x20; // 保存当前状态（用于撤销）

&#x20; saveState() {

&#x20;   this.previousState = this.editor.getValue();

&#x20; }

&#x20; // 执行命令（子类实现）

&#x20; execute() {

&#x20;   throw new Error('子类必须实现execute方法');

&#x20; }

&#x20; // 撤销命令

&#x20; undo() {

&#x20;   this.editor.setValue(this.previousState);

&#x20; }

}

// 具体命令：插入文本

class InsertCommand extends EditorCommand {

&#x20; constructor(editor, text, position) {

&#x20;   super(editor);

&#x20;   this.text = text;

&#x20;   this.position = position;

&#x20; }

&#x20; execute() {

&#x20;   this.saveState();

&#x20;   const currentValue = this.editor.getValue();

&#x20;   const newValue = currentValue.slice(0, this.position) + this.text + currentValue.slice(this.position);

&#x20;   this.editor.setValue(newValue);

&#x20; }

}

// 具体命令：删除文本

class DeleteCommand extends EditorCommand {

&#x20; constructor(editor, start, end) {

&#x20;   super(editor);

&#x20;   this.start = start;

&#x20;   this.end = end;

&#x20; }

&#x20; execute() {

&#x20;   this.saveState();

&#x20;   const currentValue = this.editor.getValue();

&#x20;   const deletedText = currentValue.slice(this.start, this.end);

&#x20;   this.deletedText = deletedText; // 保存删除的文本，用于重做

&#x20;   const newValue = currentValue.slice(0, this.start) + currentValue.slice(this.end);

&#x20;   this.editor.setValue(newValue);

&#x20; }

&#x20; // 重做删除操作（覆盖父类方法）

&#x20; undo() {

&#x20;   const currentValue = this.editor.getValue();

&#x20;   const newValue = currentValue.slice(0, this.start) + this.deletedText + currentValue.slice(this.start);

&#x20;   this.editor.setValue(newValue);

&#x20; }

}

// 调用者：命令管理器

class CommandManager {

&#x20; constructor() {

&#x20;   this.commandStack = \[];

&#x20;   this.undoStack = \[];

&#x20; }

&#x20; executeCommand(command) {

&#x20;   command.execute();

&#x20;   this.commandStack.push(command);

&#x20;   this.undoStack = \[]; // 执行新命令后清空重做栈

&#x20; }

&#x20; undo() {

&#x20;   if (this.commandStack.length === 0) return;

&#x20;   const command = this.commandStack.pop();

&#x20;   command.undo();

&#x20;   this.undoStack.push(command);

&#x20; }

&#x20; redo() {

&#x20;   if (this.undoStack.length === 0) return;

&#x20;   const command = this.undoStack.pop();

&#x20;   command.execute();

&#x20;   this.commandStack.push(command);

&#x20; }

}

// 编辑器实例（接收者）

const editor = {

&#x20; value: '',

&#x20; getValue() { return this.value; },

&#x20; setValue(val) { this.value = val; console.log('编辑器内容:', val); }

};

// 使用示例

const commandManager = new CommandManager();

// 执行插入命令

commandManager.executeCommand(new InsertCommand(editor, 'Hello ', 0));

// 执行删除命令

commandManager.executeCommand(new DeleteCommand(editor, 5, 6));

commandManager.undo(); // 撤销删除

commandManager.redo(); // 重做删除
```

**适用原因**：



*   每个编辑操作（插入、删除）都是独立的 “命令”，可被统一管理

*   需要支持撤销 / 重做功能，命令模式的 `undo()` 方法天然适合

*   便于记录操作日志（通过遍历命令栈），支持断点续传或操作回放

##### （2）批量任务调度

前端需要按顺序执行多个异步任务（如表单提交前的验证、数据处理、API 请求）时，命令模式可实现任务队列管理：



```
// 异步命令基类

class AsyncCommand {

&#x20; constructor(context) {

&#x20;   this.context = context;

&#x20; }

&#x20; async execute() { throw new Error('子类必须实现execute方法'); }

}

// 具体命令：表单验证

class ValidateCommand extends AsyncCommand {

&#x20; async execute() {

&#x20;   console.log('执行表单验证');

&#x20;   // 模拟验证逻辑

&#x20;   if (!this.context.formData.username) {

&#x20;     throw new Error('用户名不能为空');

&#x20;   }

&#x20;   return true;

&#x20; }

}

// 具体命令：数据格式化

class FormatCommand extends AsyncCommand {

&#x20; async execute() {

&#x20;   console.log('执行数据格式化');

&#x20;   this.context.formattedData = {

&#x20;     ...this.context.formData,

&#x20;     timestamp: Date.now()

&#x20;   };

&#x20;   return this.context.formattedData;

&#x20; }

}

// 具体命令：API提交

class SubmitCommand extends AsyncCommand {

&#x20; async execute() {

&#x20;   console.log('执行API提交');

&#x20;   // 模拟API请求

&#x20;   return new Promise(resolve => {

&#x20;     setTimeout(() => {

&#x20;       resolve({ success: true, id: '123' });

&#x20;     }, 1000);

&#x20;   });

&#x20; }

}

// 命令队列管理器

class CommandQueue {

&#x20; constructor() {

&#x20;   this.queue = \[];

&#x20; }

&#x20; addCommand(command) {

&#x20;   this.queue.push(command);

&#x20; }

&#x20; async executeAll() {

&#x20;   try {

&#x20;     for (const command of this.queue) {

&#x20;       await command.execute();

&#x20;     }

&#x20;     console.log('所有命令执行完成');

&#x20;     this.queue = \[];

&#x20;   } catch (error) {

&#x20;     console.error('命令执行失败:', error.message);

&#x20;   }

&#x20; }

}

// 使用示例

const context = { formData: { username: 'test' } };

const queue = new CommandQueue();

queue.addCommand(new ValidateCommand(context));

queue.addCommand(new FormatCommand(context));

queue.addCommand(new SubmitCommand(context));

queue.executeAll(); // 按顺序执行所有命令
```

**适用原因**：



*   每个任务被封装为命令，可灵活添加 / 移除，便于扩展

*   支持按顺序执行，前一个命令失败时可终止后续执行

*   便于添加日志记录、异常处理等横切关注点

#### 2. 策略模式的典型应用场景

##### （1）表单验证规则的动态切换

表单中不同字段需要不同的验证规则（如手机号、邮箱、密码），策略模式可实现规则的灵活组合与切换：



```
// 策略接口：验证策略

class ValidationStrategy {

&#x20; validate(value) { throw new Error('子类必须实现validate方法'); }

}

// 具体策略：手机号验证

class PhoneStrategy extends ValidationStrategy {

&#x20; validate(value) {

&#x20;   const regex = /^1\[3-9]\d{9}\$/;

&#x20;   if (!regex.test(value)) {

&#x20;     return { valid: false, message: '请输入正确的手机号' };

&#x20;   }

&#x20;   return { valid: true };

&#x20; }

}

// 具体策略：邮箱验证

class EmailStrategy extends ValidationStrategy {

&#x20; validate(value) {

&#x20;   const regex = /^\[^\s@]+@\[^\s@]+\\.\[^\s@]+\$/;

&#x20;   if (!regex.test(value)) {

&#x20;     return { valid: false, message: '请输入正确的邮箱' };

&#x20;   }

&#x20;   return { valid: true };

&#x20; }

}

// 具体策略：密码强度验证

class PasswordStrategy extends ValidationStrategy {

&#x20; constructor(minLength = 6) {

&#x20;   super();

&#x20;   this.minLength = minLength;

&#x20; }

&#x20; validate(value) {

&#x20;   if (value.length < this.minLength) {

&#x20;     return { valid: false, message: \`密码长度不能少于\${this.minLength}位\` };

&#x20;   }

&#x20;   if (!/\[A-Z]/.test(value)) {

&#x20;     return { valid: false, message: '密码需包含大写字母' };

&#x20;   }

&#x20;   return { valid: true };

&#x20; }

}

// 上下文：表单验证器

class FormValidator {

&#x20; constructor() {

&#x20;   this.strategies = {}; // 存储字段与策略的映射

&#x20; }

&#x20; // 为字段添加验证策略

&#x20; addField(field, strategy) {

&#x20;   this.strategies\[field] = strategy;

&#x20; }

&#x20; // 执行验证

&#x20; validate(formData) {

&#x20;   const errors = {};

&#x20;   for (const \[field, strategy] of Object.entries(this.strategies)) {

&#x20;     const result = strategy.validate(formData\[field]);

&#x20;     if (!result.valid) {

&#x20;       errors\[field] = result.message;

&#x20;     }

&#x20;   }

&#x20;   return {

&#x20;     valid: Object.keys(errors).length === 0,

&#x20;     errors

&#x20;   };

&#x20; }

}

// 使用示例

const validator = new FormValidator();

// 为不同字段添加不同策略

validator.addField('phone', new PhoneStrategy());

validator.addField('email', new EmailStrategy());

validator.addField('password', new PasswordStrategy(8));

// 验证表单数据

const formData = {

&#x20; phone: '13800138000',

&#x20; email: 'test@example.com',

&#x20; password: 'pass123'

};

const result = validator.validate(formData);

console.log('验证结果:', result);
```

**适用原因**：



*   每种验证规则是独立的策略，可单独维护、测试

*   支持动态为字段切换策略（如密码验证可根据场景切换强度）

*   便于扩展新规则（只需新增策略类，无需修改验证器核心逻辑）

##### （2）数据可视化的渲染策略

图表组件需要支持多种渲染方式（如折线图、柱状图、饼图）时，策略模式可实现渲染逻辑的解耦：



```
// 策略接口：图表渲染策略

class ChartStrategy {

&#x20; render(data, container) { throw new Error('子类必须实现render方法'); }

}

// 具体策略：折线图渲染

class LineChartStrategy extends ChartStrategy {

&#x20; render(data, container) {

&#x20;   console.log(\`在\${container}中渲染折线图:\`, data);

&#x20;   // 实际实现：使用Canvas或SVG绘制折线图

&#x20; }

}

// 具体策略：柱状图渲染

class BarChartStrategy extends ChartStrategy {

&#x20; render(data, container) {

&#x20;   console.log(\`在\${container}中渲染柱状图:\`, data);

&#x20;   // 实际实现：使用Canvas或SVG绘制柱状图

&#x20; }

}

// 具体策略：饼图渲染

class PieChartStrategy extends ChartStrategy {

&#x20; render(data, container) {

&#x20;   console.log(\`在\${container}中渲染饼图:\`, data);

&#x20;   // 实际实现：使用Canvas或SVG绘制饼图

&#x20; }

}

// 上下文：图表组件

class ChartComponent {

&#x20; constructor(container) {

&#x20;   this.container = container;

&#x20;   this.strategy = new LineChartStrategy(); // 默认策略

&#x20;   this.data = \[];

&#x20; }

&#x20; // 设置数据

&#x20; setData(data) {

&#x20;   this.data = data;

&#x20;   this.render(); // 数据变化后重新渲染

&#x20; }

&#x20; // 切换渲染策略

&#x20; setType(type) {

&#x20;   switch (type) {

&#x20;     case 'line':

&#x20;       this.strategy = new LineChartStrategy();

&#x20;       break;

&#x20;     case 'bar':

&#x20;       this.strategy = new BarChartStrategy();

&#x20;       break;

&#x20;     case 'pie':

&#x20;       this.strategy = new PieChartStrategy();

&#x20;       break;

&#x20;     default:

&#x20;       throw new Error('不支持的图表类型');

&#x20;   }

&#x20;   this.render(); // 类型变化后重新渲染

&#x20; }

&#x20; // 执行渲染

&#x20; render() {

&#x20;   this.strategy.render(this.data, this.container);

&#x20; }

}

// 使用示例

const chart = new ChartComponent('#chart-container');

chart.setData(\[10, 20, 30, 40, 50]); // 使用默认折线图渲染

// 切换为柱状图

chart.setType('bar');

// 切换为饼图

chart.setType('pie');
```

**适用原因**：



*   每种图表类型的渲染逻辑是独立策略，便于维护

*   支持运行时动态切换策略（用户可点击按钮切换图表类型）

*   新增图表类型时只需添加新策略，符合开放 - 封闭原则

### 模式选择的决策指南

在前端开发中，选择命令模式还是策略模式可参考以下原则：



1.  **功能需求判断**：

*   若需要**操作管理**（撤销、日志、队列）→ 命令模式

*   若需要**算法替换**（动态切换实现方式）→ 策略模式

1.  **对象关系判断**：

*   若组件间存在**请求发送者与执行者的分离**→ 命令模式

*   若组件需要**多种算法可选**且算法独立→ 策略模式

1.  **代码演化判断**：

*   若功能扩展方向是**新增操作类型**→ 命令模式

*   若功能扩展方向是**新增实现方式**→ 策略模式

### 总结

命令模式与策略模式均通过封装实现解耦，但核心目标不同：命令模式聚焦于 “操作的执行与管理”，支持撤销、日志等功能；策略模式聚焦于 “算法的选择与替换”，支持动态切换实现。

在前端开发中，命令模式适用于富文本编辑器、任务调度等需要管理操作序列的场景；策略模式适用于表单验证、数据可视化等需要灵活切换算法的场景。理解两种模式的本质差异，能帮助开发者设计出更具灵活性和可维护性的前端系统。
