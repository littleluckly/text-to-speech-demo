## 答案 1：核心简洁的口语化回答

・策略模式是定义一系列算法，将每个算法封装起来，使它们可相互替换的设计模式

・核心是分离算法的定义与使用，通过委托让不同算法灵活切换

・主要解决大量条件判断导致的代码臃肿问题，提高可维护性

・包含策略接口、具体策略实现和使用策略的上下文三个部分

・适用于支付方式选择、表单验证规则、排序算法切换等场景

## 答案 2：口语化扩展回答

策略模式说白了就是把各种类似的算法或逻辑分开打包，让它们能互相替换着用。比如做一个电商网站的支付功能，有支付宝、微信、银行卡等多种支付方式，每种方式的实现逻辑都不一样，但对外都需要一个 "支付" 的动作，这时候就可以用策略模式来处理。

它的好处很明显，首先是去掉了一堆 if-else 判断，原来可能需要根据支付方式写很多条件分支，用了策略模式后，直接选对应的策略就行。其次是扩展方便，以后要加新的支付方式，不用改原来的代码，直接新增一个策略类就行，符合 "对扩展开放，对修改关闭" 的原则。

实际开发中，除了支付场景，表单验证也是个典型例子，不同字段有不同的验证规则（比如手机号、邮箱、密码），可以把每种规则做成策略，然后根据字段类型动态选择。还有表格排序、动画效果切换等场景，只要存在多种可替换的算法或行为，都适合用策略模式来优化代码结构。

## 答案 3：技术深度解析

### 策略模式的核心原理与结构

策略模式（Strategy Pattern）属于行为型设计模式，其核心思想是**将算法的定义与使用分离**，通过封装不同的算法（策略），使它们可以在运行时动态切换，而不影响使用算法的客户端。

策略模式的经典结构包含三个部分：



1.  **抽象策略（Strategy）**：定义所有支持算法的公共接口，通常是一个抽象类或接口

2.  **具体策略（Concrete Strategy）**：实现抽象策略定义的接口，包含具体的算法实现

3.  **上下文（Context）**：持有策略对象的引用，负责将客户端的请求委托给具体策略

这种结构实现了 "开闭原则"—— 新增策略时无需修改原有代码，只需添加新的策略实现类。

### 策略模式的实现示例

#### 1. 基础实现框架



```
// 1. 抽象策略 - 定义支付接口

class PaymentStrategy {

&#x20; /\*\*

&#x20;  \* 支付方法

&#x20;  \* @param {number} amount - 支付金额

&#x20;  \* @returns {string} 支付结果

&#x20;  \*/

&#x20; pay(amount) {

&#x20;   throw new Error("子类必须实现pay方法");

&#x20; }

}

// 2. 具体策略1 - 支付宝支付

class AlipayStrategy extends PaymentStrategy {

&#x20; /\*\*

&#x20;  \* 支付宝支付实现

&#x20;  \* @param {number} amount - 支付金额

&#x20;  \* @returns {string} 支付结果

&#x20;  \*/

&#x20; pay(amount) {

&#x20;   // 实际开发中这里会调用支付宝API

&#x20;   return \`使用支付宝支付了 \${amount} 元，交易号：\${this.generateTradeNo()}\`;

&#x20; }

&#x20;&#x20;

&#x20; /\*\*

&#x20;  \* 生成交易号（策略内部的辅助方法）

&#x20;  \* @returns {string} 唯一交易号

&#x20;  \*/

&#x20; generateTradeNo() {

&#x20;   return 'ALI' + Date.now() + Math.random().toString(36).substr(2, 8);

&#x20; }

}

// 2. 具体策略2 - 微信支付

class WechatPayStrategy extends PaymentStrategy {

&#x20; /\*\*

&#x20;  \* 微信支付实现

&#x20;  \* @param {number} amount - 支付金额

&#x20;  \* @returns {string} 支付结果

&#x20;  \*/

&#x20; pay(amount) {

&#x20;   // 实际开发中这里会调用微信支付API

&#x20;   return \`使用微信支付了 \${amount} 元，交易号：\${this.createTransactionId()}\`;

&#x20; }

&#x20;&#x20;

&#x20; /\*\*

&#x20;  \* 生成微信交易号

&#x20;  \* @returns {string} 交易ID

&#x20;  \*/

&#x20; createTransactionId() {

&#x20;   return 'WX' + Date.now() + Math.random().toString(36).substr(2, 8);

&#x20; }

}

// 3. 上下文 - 订单支付管理

class OrderPayment {

&#x20; /\*\*

&#x20;  \* 初始化订单支付

&#x20;  \* @param {PaymentStrategy} strategy - 支付策略

&#x20;  \*/

&#x20; constructor(strategy) {

&#x20;   this.strategy = strategy; // 持有策略引用

&#x20;   this.items = \[]; // 订单商品

&#x20; }

&#x20;&#x20;

&#x20; /\*\*

&#x20;  \* 添加商品

&#x20;  \* @param {string} name - 商品名称

&#x20;  \* @param {number} price - 商品价格

&#x20;  \*/

&#x20; addItem(name, price) {

&#x20;   this.items.push({ name, price });

&#x20; }

&#x20;&#x20;

&#x20; /\*\*

&#x20;  \* 计算总金额

&#x20;  \* @returns {number} 总金额

&#x20;  \*/

&#x20; calculateTotal() {

&#x20;   return this.items.reduce((total, item) => total + item.price, 0);

&#x20; }

&#x20;&#x20;

&#x20; /\*\*

&#x20;  \* 执行支付

&#x20;  \* @returns {string} 支付结果

&#x20;  \*/

&#x20; pay() {

&#x20;   const total = this.calculateTotal();

&#x20;   // 委托给具体策略执行

&#x20;   return this.strategy.pay(total);

&#x20; }

&#x20;&#x20;

&#x20; /\*\*

&#x20;  \* 动态切换支付策略

&#x20;  \* @param {PaymentStrategy} strategy - 新的支付策略

&#x20;  \*/

&#x20; setStrategy(strategy) {

&#x20;   this.strategy = strategy;

&#x20; }

}

// 使用示例

// 创建订单

const order = new OrderPayment(new AlipayStrategy());

order.addItem('手机', 3999);

order.addItem('耳机', 299);

// 用支付宝支付

console.log(order.pay()); // 输出支付宝支付结果

// 切换到微信支付

order.setStrategy(new WechatPayStrategy());

console.log(order.pay()); // 输出微信支付结果
```

#### 2. 函数式策略模式（JavaScript 特色实现）

利用 JavaScript 函数一等公民的特性，可以简化策略模式实现：



```
// 策略对象 - 直接使用函数作为策略

const validationStrategies = {

&#x20; // 手机号验证策略

&#x20; phone: (value) => {

&#x20;   const reg = /^1\[3-9]\d{9}\$/;

&#x20;   return reg.test(value) ? null : '请输入正确的手机号';

&#x20; },

&#x20;&#x20;

&#x20; // 邮箱验证策略

&#x20; email: (value) => {

&#x20;   const reg = /^\[^\s@]+@\[^\s@]+\\.\[^\s@]+\$/;

&#x20;   return reg.test(value) ? null : '请输入正确的邮箱地址';

&#x20; },

&#x20;&#x20;

&#x20; // 密码验证策略

&#x20; password: (value) => {

&#x20;   if (value.length < 6) return '密码长度不能少于6位';

&#x20;   if (!/\[A-Z]/.test(value)) return '密码必须包含大写字母';

&#x20;   return null;

&#x20; }

};

// 上下文 - 表单验证器

class FormValidator {

&#x20; /\*\*

&#x20;  \* 初始化验证器

&#x20;  \* @param {Object} rules - 验证规则 {字段名: 策略类型}

&#x20;  \*/

&#x20; constructor(rules) {

&#x20;   this.rules = rules;

&#x20; }

&#x20;&#x20;

&#x20; /\*\*

&#x20;  \* 执行验证

&#x20;  \* @param {Object} formData - 表单数据

&#x20;  \* @returns {Object} 验证结果 {字段名: 错误信息}

&#x20;  \*/

&#x20; validate(formData) {

&#x20;   const errors = {};

&#x20;  &#x20;

&#x20;   // 遍历所有规则，应用对应策略

&#x20;   Object.keys(this.rules).forEach(field => {

&#x20;     const strategyName = this.rules\[field];

&#x20;     const strategy = validationStrategies\[strategyName];

&#x20;    &#x20;

&#x20;     if (strategy) {

&#x20;       const error = strategy(formData\[field]);

&#x20;       if (error) {

&#x20;         errors\[field] = error;

&#x20;       }

&#x20;     }

&#x20;   });

&#x20;  &#x20;

&#x20;   return errors;

&#x20; }

}

// 使用示例

const loginValidator = new FormValidator({

&#x20; phone: 'phone',

&#x20; password: 'password'

});

const formData = {

&#x20; phone: '123456',

&#x20; password: '123'

};

const errors = loginValidator.validate(formData);

console.log(errors);

// 输出: {

//   phone: '请输入正确的手机号',

//   password: '密码长度不能少于6位'

// }
```

### 策略模式的典型应用场景

#### 1. 表单验证

如上述函数式实现所示，策略模式非常适合处理多字段、多规则的表单验证场景。不同字段的验证规则作为策略，可灵活组合和复用。

#### 2. 支付方式选择

电商系统中，用户可选择多种支付方式（支付宝、微信、银联等），每种支付方式的接口和流程不同，但最终目标一致（完成支付），适合用策略模式封装。

#### 3. 数据排序算法切换



```
// 排序策略

const sortStrategies = {

&#x20; // 按价格升序

&#x20; priceAsc: (products) => \[...products].sort((a, b) => a.price - b.price),

&#x20; // 按价格降序

&#x20; priceDesc: (products) => \[...products].sort((a, b) => b.price - a.price),

&#x20; // 按销量排序

&#x20; sales: (products) => \[...products].sort((a, b) => b.sales - a.sales),

&#x20; // 按评分排序

&#x20; rating: (products) => \[...products].sort((a, b) => b.rating - a.rating)

};

// 商品列表管理器

class ProductList {

&#x20; constructor(products) {

&#x20;   this.products = products;

&#x20;   this.strategy = sortStrategies.priceAsc; // 默认策略

&#x20; }

&#x20;&#x20;

&#x20; setSortStrategy(strategyName) {

&#x20;   this.strategy = sortStrategies\[strategyName] || sortStrategies.priceAsc;

&#x20; }

&#x20;&#x20;

&#x20; getSortedProducts() {

&#x20;   return this.strategy(this.products);

&#x20; }

}

// 使用

const products = \[

&#x20; { name: '商品A', price: 100, sales: 10, rating: 4.5 },

&#x20; { name: '商品B', price: 50, sales: 20, rating: 4.8 },

&#x20; { name: '商品C', price: 150, sales: 5, rating: 4.2 }

];

const productList = new ProductList(products);

productList.setSortStrategy('sales');

console.log(productList.getSortedProducts()); // 按销量排序
```

#### 4. 动画效果切换

在前端动画库中，可使用策略模式封装不同的动画算法（线性、弹跳、减速等）：



```
// 动画策略

const animationStrategies = {

&#x20; linear: (t, b, c, d) => {

&#x20;   // 线性动画：t(当前时间)/d(总时间) \* c(变化量) + b(初始值)

&#x20;   return c \* t / d + b;

&#x20; },

&#x20; easeOut: (t, b, c, d) => {

&#x20;   // 减速动画

&#x20;   t /= d;

&#x20;   return -c \* t \* (t - 2) + b;

&#x20; },

&#x20; bounce: (t, b, c, d) => {

&#x20;   // 弹跳动画

&#x20;   t /= d;

&#x20;   if (t < 1/2.75) {

&#x20;     return c\*(7.5625\*t\*t) + b;

&#x20;   } else if (t < 2/2.75) {

&#x20;     t -= 1.5/2.75;

&#x20;     return c\*(7.5625\*t\*t + .75) + b;

&#x20;   } else if (t < 2.5/2.75) {

&#x20;     t -= 2.25/2.75;

&#x20;     return c\*(7.5625\*t\*t + .9375) + b;

&#x20;   } else {

&#x20;     t -= 2.625/2.75;

&#x20;     return c\*(7.5625\*t\*t + .984375) + b;

&#x20;   }

&#x20; }

};

// 动画控制器

class Animator {

&#x20; constructor(element, strategy = 'linear') {

&#x20;   this.element = element;

&#x20;   this.strategy = animationStrategies\[strategy];

&#x20;   this.startTime = null;

&#x20;   this.duration = 1000; // 动画时长1秒

&#x20; }

&#x20;&#x20;

&#x20; setStrategy(strategyName) {

&#x20;   this.strategy = animationStrategies\[strategyName] || animationStrategies.linear;

&#x20; }

&#x20;&#x20;

&#x20; animate(from, to) {

&#x20;   this.startTime = Date.now();

&#x20;   const change = to - from;

&#x20;   const startValue = from;

&#x20;  &#x20;

&#x20;   const step = () => {

&#x20;     const currentTime = Date.now() - this.startTime;

&#x20;     if (currentTime < this.duration) {

&#x20;       // 应用当前策略计算位置

&#x20;       const value = this.strategy(currentTime, startValue, change, this.duration);

&#x20;       this.element.style.left = \`\${value}px\`;

&#x20;       requestAnimationFrame(step);

&#x20;     } else {

&#x20;       this.element.style.left = \`\${to}px\`;

&#x20;     }

&#x20;   };

&#x20;  &#x20;

&#x20;   requestAnimationFrame(step);

&#x20; }

}

// 使用

const box = document.getElementById('box');

const animator = new Animator(box, 'bounce');

animator.animate(0, 500); // 从0px动画到500px，使用弹跳效果
```

### 策略模式的优缺点分析

**优点**：



*   消除大量条件判断语句，使代码更清晰

*   符合开闭原则，扩展新策略无需修改原有代码

*   策略可复用，不同场景可共享相同策略实现

*   便于单元测试，每个策略可独立测试

**缺点**：



*   增加了系统中类的数量（传统实现）

*   客户端必须了解所有策略的区别，才能选择合适的策略

*   策略间不能直接通信，如需共享数据需通过上下文

### 策略模式与其他模式的对比



1.  **策略模式 vs 工厂模式**：

*   策略模式注重算法的封装与切换

*   工厂模式注重对象的创建

*   两者可结合使用：工厂负责创建策略对象，策略负责具体算法

1.  **策略模式 vs 状态模式**：

*   策略模式中，客户端主动选择并切换策略

*   状态模式中，状态由上下文根据情况自动切换

*   策略模式中策略间无依赖，状态模式中状态间可能存在转换关系

### 总结

策略模式是处理算法多样性的优秀解决方案，尤其适合那些需要在运行时根据不同条件切换不同逻辑的场景。在 JavaScript 中，由于函数是一等公民，我们可以用更简洁的方式实现策略模式，无需严格遵循类的继承结构。

使用策略模式的关键在于识别出系统中可能变化的部分（算法、规则、行为），将其封装为独立策略，而保持稳定的部分（使用策略的逻辑）。这种分离不仅使代码更具可读性和可维护性，也为未来的扩展提供了便利。

在实际开发中，应避免过度使用策略模式。当算法简单且不会频繁变化时，直接使用条件判断可能更简洁。只有当算法复杂、多变且需要频繁切换时，策略模式才能发挥其最大价值。
