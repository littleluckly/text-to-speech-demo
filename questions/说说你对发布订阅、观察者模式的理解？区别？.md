## 答案 1：核心简洁的口语化回答

・观察者模式中，观察者直接依赖被观察者，被观察者状态变化时直接通知观察者

・发布订阅模式有中间层（事件总线），发布者和订阅者互不依赖，通过事件名通信

・观察者模式是松耦合，发布订阅模式是完全解耦

・观察者模式中被观察者知道观察者的存在，发布订阅中双方互不了解

・观察者模式多用于单个对象与多个依赖对象的联动，发布订阅多用于跨模块通信

## 答案 2：口语化扩展回答

观察者模式就像老师和学生的关系，老师（被观察者）知道哪些学生（观察者）在听他讲课，当老师讲新内容时，会直接告诉这些学生。比如一个数据对象变化了，所有依赖它的 UI 组件会直接收到通知并更新，这里数据对象清楚地知道有哪些组件依赖它。

发布订阅模式更像报纸订阅，订报人（订阅者）向报社（事件中心）订阅报纸，报社收到订户后，当有新报纸出版（发布事件），就会按订阅列表把报纸发给订户。发布者和订阅者完全不认识，发布者只需要把消息发给事件中心，订阅者也只从事件中心获取自己关心的消息，双方没有直接联系。

实际开发中，观察者模式适合局部的状态管理，比如组件内部的状态变化通知。而发布订阅模式更适合跨组件、跨模块的通信，比如前端的事件总线、全局状态管理，或者后端的消息队列，能有效减少模块间的直接依赖，让系统更灵活。

## 答案 3：技术深度解析

### 两种模式的核心定义与实现

#### 1. 观察者模式（Observer Pattern）

观察者模式定义了对象间的一对多依赖关系，当一个对象（被观察者）的状态发生改变时，所有依赖它的对象（观察者）都会自动收到通知并更新。

**经典实现**：



```
// 被观察者（主题）

class Subject {

&#x20; constructor() {

&#x20;   this.observers = \[]; // 存储所有观察者

&#x20; }

&#x20;&#x20;

&#x20; // 添加观察者

&#x20; addObserver(observer) {

&#x20;   // 确保观察者实现了update方法

&#x20;   if (typeof observer.update === 'function') {

&#x20;     this.observers.push(observer);

&#x20;   } else {

&#x20;     throw new Error('观察者必须实现update方法');

&#x20;   }

&#x20; }

&#x20;&#x20;

&#x20; // 移除观察者

&#x20; removeObserver(observer) {

&#x20;   this.observers = this.observers.filter(obs => obs !== observer);

&#x20; }

&#x20;&#x20;

&#x20; // 通知所有观察者

&#x20; notify(data) {

&#x20;   // 遍历所有观察者并调用其update方法

&#x20;   this.observers.forEach(observer => {

&#x20;     observer.update(data);

&#x20;   });

&#x20; }

&#x20;&#x20;

&#x20; // 业务方法：改变状态并通知

&#x20; setState(newState) {

&#x20;   this.state = newState;

&#x20;   this.notify(newState); // 状态改变后立即通知

&#x20; }

}

// 观察者

class Observer {

&#x20; /\*\*

&#x20;  \* 构造函数

&#x20;  \* @param {string} name - 观察者名称，用于区分

&#x20;  \*/

&#x20; constructor(name) {

&#x20;   this.name = name;

&#x20; }

&#x20;&#x20;

&#x20; /\*\*

&#x20;  \* 接收通知的方法（必须实现）

&#x20;  \* @param {any} data - 被观察者传递的数据

&#x20;  \*/

&#x20; update(data) {

&#x20;   console.log(\`\${this.name} 收到更新:\`, data);

&#x20;   // 这里可以添加具体的处理逻辑

&#x20;   this.handleUpdate(data);

&#x20; }

&#x20;&#x20;

&#x20; /\*\*

&#x20;  \* 具体处理逻辑（子类可重写）

&#x20;  \* @param {any} data - 数据

&#x20;  \*/

&#x20; handleUpdate(data) {

&#x20;   // 默认实现

&#x20; }

}

// 具体观察者1：日志记录器

class LoggerObserver extends Observer {

&#x20; handleUpdate(data) {

&#x20;   console.log(\`\[日志] 记录数据变化: \${JSON.stringify(data)}\`);

&#x20; }

}

// 具体观察者2：UI更新器

class UIObserver extends Observer {

&#x20; handleUpdate(data) {

&#x20;   console.log(\`\[UI] 更新界面显示: \${JSON.stringify(data)}\`);

&#x20; }

}

// 使用示例

const subject = new Subject();

const logger = new LoggerObserver('日志观察者');

const ui = new UIObserver('UI观察者');

// 添加观察者

subject.addObserver(logger);

subject.addObserver(ui);

// 改变状态，会自动通知所有观察者

subject.setState({ name: '测试', value: 100 });

// 输出：

// 日志观察者 收到更新: { name: '测试', value: 100 }

// \[日志] 记录数据变化: {"name":"测试","value":100}

// UI观察者 收到更新: { name: '测试', value: 100 }

// \[UI] 更新界面显示: {"name":"测试","value":100}
```

**核心特点**：



*   被观察者直接持有观察者的引用

*   通知方式是直接调用观察者的更新方法

*   观察者和被观察者是双向依赖关系

*   通常是同步通知

#### 2. 发布订阅模式（Publish-Subscribe Pattern）

发布订阅模式引入了一个中间层（事件总线 / 事件中心），发布者通过事件中心发布事件，订阅者通过事件中心订阅事件，双方互不直接通信。

**经典实现**：



```
// 事件中心（中间层）

class EventBus {

&#x20; constructor() {

&#x20;   // 存储事件订阅关系：{ 事件名: \[回调函数数组] }

&#x20;   this.events = {};

&#x20; }

&#x20;&#x20;

&#x20; /\*\*

&#x20;  \* 订阅事件

&#x20;  \* @param {string} eventName - 事件名称

&#x20;  \* @param {Function} callback - 回调函数

&#x20;  \* @param {any} context - 回调函数的上下文（可选）

&#x20;  \* @returns {Function} 取消订阅的函数

&#x20;  \*/

&#x20; subscribe(eventName, callback, context) {

&#x20;   // 如果事件不存在，初始化一个空数组

&#x20;   if (!this.events\[eventName]) {

&#x20;     this.events\[eventName] = \[];

&#x20;   }

&#x20;  &#x20;

&#x20;   // 存储订阅信息

&#x20;   const subscription = {

&#x20;     callback: context ? callback.bind(context) : callback,

&#x20;     context

&#x20;   };

&#x20;  &#x20;

&#x20;   this.events\[eventName].push(subscription);

&#x20;  &#x20;

&#x20;   // 返回取消订阅的函数

&#x20;   return () => {

&#x20;     this.unsubscribe(eventName, callback, context);

&#x20;   };

&#x20; }

&#x20;&#x20;

&#x20; /\*\*

&#x20;  \* 取消订阅

&#x20;  \* @param {string} eventName - 事件名称

&#x20;  \* @param {Function} callback - 要取消的回调函数

&#x20;  \* @param {any} context - 回调函数的上下文

&#x20;  \*/

&#x20; unsubscribe(eventName, callback, context) {

&#x20;   if (!this.events\[eventName]) return;

&#x20;  &#x20;

&#x20;   // 过滤掉要取消的订阅

&#x20;   this.events\[eventName] = this.events\[eventName].filter(sub => {

&#x20;     // 匹配回调函数和上下文

&#x20;     return !(sub.callback === callback ||&#x20;

&#x20;             (sub.callback === callback.bind(context) && sub.context === context));

&#x20;   });

&#x20;  &#x20;

&#x20;   // 如果事件没有订阅者了，删除该事件

&#x20;   if (this.events\[eventName].length === 0) {

&#x20;     delete this.events\[eventName];

&#x20;   }

&#x20; }

&#x20;&#x20;

&#x20; /\*\*

&#x20;  \* 发布事件

&#x20;  \* @param {string} eventName - 事件名称

&#x20;  \* @param {...any} args - 传递给订阅者的参数

&#x20;  \*/

&#x20; publish(eventName, ...args) {

&#x20;   if (!this.events\[eventName]) return;

&#x20;  &#x20;

&#x20;   // 复制一份订阅列表，防止在回调中修改原数组导致问题

&#x20;   const subscriptions = \[...this.events\[eventName]];

&#x20;  &#x20;

&#x20;   // 调用所有订阅者的回调函数

&#x20;   subscriptions.forEach(subscription => {

&#x20;     subscription.callback(...args);

&#x20;   });

&#x20; }

&#x20;&#x20;

&#x20; /\*\*

&#x20;  \* 订阅一次事件（触发后自动取消订阅）

&#x20;  \* @param {string} eventName - 事件名称

&#x20;  \* @param {Function} callback - 回调函数

&#x20;  \* @param {any} context - 上下文

&#x20;  \*/

&#x20; once(eventName, callback, context) {

&#x20;   // 创建一个包装函数，执行后自动取消订阅

&#x20;   const wrapper = (...args) => {

&#x20;     callback.apply(context, args);

&#x20;     this.unsubscribe(eventName, wrapper);

&#x20;   };

&#x20;  &#x20;

&#x20;   this.subscribe(eventName, wrapper, context);

&#x20; }

}

// 发布者1：用户服务

class UserService {

&#x20; constructor(eventBus) {

&#x20;   this.eventBus = eventBus;

&#x20; }

&#x20;&#x20;

&#x20; // 用户登录

&#x20; login(userInfo) {

&#x20;   console.log('用户登录成功:', userInfo);

&#x20;   // 发布登录成功事件

&#x20;   this.eventBus.publish('userLoggedIn', userInfo);

&#x20; }

&#x20;&#x20;

&#x20; // 用户登出

&#x20; logout() {

&#x20;   console.log('用户登出');

&#x20;   // 发布登出事件

&#x20;   this.eventBus.publish('userLoggedOut');

&#x20; }

}

// 发布者2：购物车服务

class CartService {

&#x20; constructor(eventBus) {

&#x20;   this.eventBus = eventBus;

&#x20;   this.items = \[];

&#x20; }

&#x20;&#x20;

&#x20; // 添加商品到购物车

&#x20; addItem(item) {

&#x20;   this.items.push(item);

&#x20;   console.log('添加商品到购物车:', item);

&#x20;   // 发布购物车更新事件

&#x20;   this.eventBus.publish('cartUpdated', this.items);

&#x20; }

}

// 订阅者1：导航组件

class NavComponent {

&#x20; constructor(eventBus) {

&#x20;   this.eventBus = eventBus;

&#x20;   // 订阅用户登录和登出事件

&#x20;   this.eventBus.subscribe('userLoggedIn', this.handleLogin, this);

&#x20;   this.eventBus.subscribe('userLoggedOut', this.handleLogout, this);

&#x20; }

&#x20;&#x20;

&#x20; handleLogin(userInfo) {

&#x20;   console.log('导航栏更新：显示用户', userInfo.name);

&#x20; }

&#x20;&#x20;

&#x20; handleLogout() {

&#x20;   console.log('导航栏更新：显示登录按钮');

&#x20; }

}

// 订阅者2：购物车组件

class CartComponent {

&#x20; constructor(eventBus) {

&#x20;   this.eventBus = eventBus;

&#x20;   // 订阅购物车更新事件

&#x20;   this.eventBus.subscribe('cartUpdated', this.handleCartUpdate, this);

&#x20; }

&#x20;&#x20;

&#x20; handleCartUpdate(items) {

&#x20;   console.log('购物车组件更新：商品数量', items.length);

&#x20; }

}

// 使用示例

const eventBus = new EventBus();

// 创建发布者

const cartService = new CartService(eventBus);

// 创建订阅者

const cartComponent = new CartComponent(eventBus);

// 执行操作，触发事件

cartService.addItem({ id: 101, name: '商品A' });

userService.logout();

// 输出：

// 用户登录成功: { id: 1, name: '张三' }

// 导航栏更新：显示用户 张三

// 添加商品到购物车: { id: 101, name: '商品A' }

// 购物车组件更新：商品数量 1

// 用户登出

// 导航栏更新：显示登录按钮
```

**核心特点**：



*   发布者和订阅者完全解耦，互不了解对方存在

*   通过事件中心进行通信，事件名是唯一的纽带

*   支持多对多通信，一个事件可以有多个发布者和订阅者

*   可实现同步或异步通信

### 两种模式的核心区别



| 对比维度 | 观察者模式         | 发布订阅模式         |
| ---- | ------------- | -------------- |
| 依赖关系 | 被观察者直接依赖观察者   | 无直接依赖，通过中间层通信  |
| 耦合程度 | 松耦合（双方互相知晓）   | 完全解耦（双方互不知晓）   |
| 通信方式 | 直接调用观察者的更新方法  | 通过事件中心和事件名间接通信 |
| 中间层  | 无             | 有（事件总线 / 事件中心） |
| 适用场景 | 局部模块内的状态同步    | 跨模块、跨系统的消息传递   |
| 灵活性  | 较低，扩展需要修改被观察者 | 较高，扩展只需新增事件    |
| 事件粒度 | 针对被观察者的状态变化   | 针对特定事件类型       |
| 典型应用 | Vue 的响应式系统    | 事件总线、消息队列      |

### 实际开发中的应用场景对比

#### 1. 观察者模式的典型应用

**Vue 响应式系统**：

Vue 的响应式原理核心是观察者模式，当数据对象（被观察者）发生变化时，依赖它的组件（观察者）会自动更新。



```
// Vue响应式简化模型

class VueObserver {

&#x20; constructor(data) {

&#x20;   this.data = data;

&#x20;   this.dep = new Dep(); // 依赖收集器（相当于Subject）

&#x20;   this.walk(data);

&#x20; }

&#x20;&#x20;

&#x20; walk(data) {

&#x20;   Object.keys(data).forEach(key => {

&#x20;     this.defineReactive(data, key, data\[key]);

&#x20;   });

&#x20; }

&#x20;&#x20;

&#x20; defineReactive(obj, key, val) {

&#x20;   const dep = this.dep;

&#x20;   // 递归观察子属性

&#x20;   const childOb = observe(val);

&#x20;  &#x20;

&#x20;   Object.defineProperty(obj, key, {

&#x20;     get() {

&#x20;       // 依赖收集：当访问属性时，将当前Watcher添加到依赖中

&#x20;       if (Dep.target) {

&#x20;         dep.depend();

&#x20;         if (childOb) {

&#x20;           childOb.dep.depend();

&#x20;         }

&#x20;       }

&#x20;       return val;

&#x20;     },

&#x20;     set(newVal) {

&#x20;       if (val === newVal) return;

&#x20;       val = newVal;

&#x20;       // 通知更新：当属性变化时，通知所有依赖（Watcher）

&#x20;       dep.notify();

&#x20;     }

&#x20;   });

&#x20; }

}

// 依赖收集器（Subject）

class Dep {

&#x20; constructor() {

&#x20;   this.subs = \[]; // 存储Watcher（观察者）

&#x20; }

&#x20;&#x20;

&#x20; depend() {

&#x20;   if (Dep.target) {

&#x20;     Dep.target.addDep(this);

&#x20;   }

&#x20; }

&#x20;&#x20;

&#x20; notify() {

&#x20;   this.subs.forEach(sub => sub.update());

&#x20; }

}

// 观察者（Watcher）

class Watcher {

&#x20; constructor(vm, expOrFn, cb) {

&#x20;   this.vm = vm;

&#x20;   this.cb = cb;

&#x20;   this.getter = parsePath(expOrFn);

&#x20;   this.value = this.get();

&#x20; }

&#x20;&#x20;

&#x20; get() {

&#x20;   Dep.target = this;

&#x20;   const value = this.getter.call(this.vm, this.vm);

&#x20;   Dep.target = null;

&#x20;   return value;

&#x20; }

&#x20;&#x20;

&#x20; update() {

&#x20;   const oldValue = this.value;

&#x20;   this.value = this.get();

&#x20;   this.cb.call(this.vm, this.value, oldValue);

&#x20; }

}
```

#### 2. 发布订阅模式的典型应用

**前端事件总线**：

在大型应用中，跨组件通信常使用事件总线（EventBus），这是发布订阅模式的典型应用。

**Node.js 的 EventEmitter**：

Node.js 内置的 EventEmitter 是发布订阅模式的经典实现，广泛用于模块间通信。



```
// Node.js中使用EventEmitter

const EventEmitter = require('events');

// 创建事件发射器（事件中心）

const emitter = new EventEmitter();

// 订阅事件

emitter.on('message', (data) => {

&#x20; console.log('收到消息:', data);

});

// 发布事件

emitter.emit('message', 'Hello World');

// 一次性订阅

emitter.once('onceEvent', () => {

&#x20; console.log('这个事件只会触发一次');

});

emitter.emit('onceEvent'); // 会触发

emitter.emit('onceEvent'); // 不会触发
```

### 模式选择的实践建议



1.  **当需要局部状态同步时**：

*   选择观察者模式，如组件内部的状态管理、数据与视图的绑定

1.  **当需要跨模块通信时**：

*   选择发布订阅模式，如微前端应用的模块通信、前后端消息传递

1.  **当系统复杂度较低时**：

*   观察者模式实现更简单，无需额外的事件中心

1.  **当系统模块较多且需要灵活扩展时**：

*   发布订阅模式更适合，可减少模块间的直接依赖

1.  **性能考量**：

*   观察者模式通常性能更好（无中间层开销）

*   发布订阅模式因中间层存在一定性能损耗，但可通过优化事件中心减轻

### 总结

观察者模式和发布订阅模式本质上都是解决对象间通信的设计模式，核心思想都是 "事件驱动"。它们的主要区别在于耦合程度和通信方式：



*   观察者模式是 "直接通信"，被观察者直接通知观察者，适合简单的依赖关系

*   发布订阅模式是 "间接通信"，通过事件中心中转，适合复杂的系统架构
